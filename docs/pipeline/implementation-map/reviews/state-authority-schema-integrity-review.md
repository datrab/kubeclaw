# 1. Domain Health Assessment

The mapped architecture has a strong intended direction: lifecycle events/read-models and typed completion adjudication are named as canonical state layers, with legacy JSON files demoted to diagnostic/operator evidence. However, the three target maps are not internally consistent. Several verification/path rows still call `status.json`, gate-status JSON, and active-session JSON “authority” even where the authority and schema maps say lifecycle read-models or adjudicated completion evidence must win. Path construction is improved by `core/paths.js` and OI-39 boundary helpers, but the maps still expose unbounded or environment-assumed paths in CLI prompt input, delivery-lint config, status payloads, legacy adapter aliases, and OpenClaw transcript discovery.

# 2. Critical Structural Flaws (Must Fix)

1. **Module lifecycle authority is split between lifecycle read-models and legacy `status.json`.**
   `authority-map.md` states lifecycle read-models are canonical scheduler/status authority and `status.json` is a write-only diagnostic snapshot (`P14-A002`, `P14-A008`, `P15-A007`). `data-schemas.md` reinforces this by naming module read-model entries “Module scheduler authority” and saying explicit snapshot resolution is diagnostic only and `loadStatus` no longer reads `status.json` (`P14-D005`, `P15-D004`). But `path-construction.md` still says module `status.json` is loaded to determine routing (`P08-P001`), signal shutdown loads/saves it (`P04-P006`), and multiple verification rows call it canonical/module lifecycle authority (`V02a3-P001`, `V02b-P002`, `V03a-P003`). This is a direct split-brain: recovery/scheduling behavior can be specified against two different stores.

2. **Gate-status JSON precedence required explicit collapse.**
   Resolved by RV-28: lifecycle/read-model projection owns gate scheduler, recovery, dependency, and approval wait authority (`authority-map.md:P15-A004`; `data-schemas.md:P14-D006`, `P15-D005`); typed gate output owns Buster terminal completion (`data-schemas.md:P15-D006`); `gate-status.json` is only approval wait-source evidence for approval gates or diagnostic evidence for other gates (`path-construction.md:P12-P001`, `P15-P003`, `V02a1-P001`, `V04c-P005`). Local filesystem cooldown branches were removed so domain cooldowns require Redis/completion evidence rather than filesystem state.

3. **Active-session identity has too many competing authority surfaces.**
   The authority map says lifecycle read-models remain authoritative for gate/review active-session recovery and file/tracked entries are evidence only (`P09-A006`, `P10-A006`, `V04a-A004`). It also separately assigns active child-session records to lifecycle/gateway and process-local tracked entries to `tracked-agents.js` (`C00b-A002`, `C00b-A003`). The path map duplicates persisted active-session JSON paths (`P04-P004`, `C00b-P003`) and still labels gate active-session/status artifacts as “authority for stale recovery and approval reuse” (`V02b-P003`), while other rows say gate active-session files are recovery evidence only (`P09-P003`, `V04a-P005`). This ambiguity can cause stale recovery to choose between lifecycle read-model identity, active-session JSON, process-local tracked state, and gateway live status.

4. **Path-boundary policy is inconsistently applied outside the OI-39 helpers.**
   `authority-map.md` and `path-construction.md` establish `core/paths.js` as canonical and OI-39/RV-30 as the swarm/repo artifact boundary (`P01-A007`, `OI39-A001`, `OI39-A002`). RV-07 closed the delivery-lint gap by routing declared `test_config.serve.dockerfile` values through repo-root-relative and realpath-jail helpers (`path-construction.md:P02-P007`). RV-31 closed the Buster status side-channel by removing orchestrator status-file paths from module task payloads and rejecting stale payloads at validation. RV-30 closed the remaining task-path gap by producing module/gate Buster refs through `core/paths.js` and rejecting absolute/traversal task payload paths during Buster preflight (`path-construction.md:P05-P001`, `P05-P002`, `P05-P003`, `P05-P005`).

# 3. Simplification & Consolidation Targets (Should Fix)

1. **Delete scheduler/recovery language from legacy status rows.** Keep `status.json` only as explicit operator/debug evidence. Update or delete path rows that call it canonical lifecycle authority, routing input, or module state authority (`path-construction.md:P08-P001`, `V02a3-P001`, `V02b-P002`, `V03a-P003`) so they match `authority-map.md:P14-A008`, `authority-map.md:P15-A007`, and `data-schemas.md:P15-D004`.

2. **Collapse gate-status semantics into two explicit roles.** Resolved by RV-28: lifecycle/read-models plus gate output own authority; gate-status JSON is either approval wait-source evidence or diagnostic evidence. `path-construction.md:P12-P001`, `P15-P003`, and `V02a1-P001` now align with `data-schemas.md:P14-D006`, `P15-D005`, and `P15-D006`.

3. **Merge active-session schemas and path rows.** `data-schemas.md:P04-D004` and `C00b-D004` describe the same persisted active-session JSON family, while `path-construction.md:P04-P004` and `C00b-P003` duplicate the state-file path. Keep one canonical C00b lifecycle/gateway contract and make P04 rows aliases, then keep gate-specific `active-session.json` only as recovery evidence per `authority-map.md:P09-A006` and `V04a-A004`.

4. **Buster payload state side-channel removed.** Resolved by RV-31: module Buster task payloads carry only completion artifact and canonical identity fields; Buster rejects stale orchestrator status-file path fields during task validation, and lifecycle state returns through Redis completion identity (`data-schemas.md:P05-D005`, `P17-D002`, `P17-D006a`; `path-construction.md:P17-P001`).

5. **Normalize CLI flags to one schema.** Resolved by RV-32: `skills/nova/pipeline/cli.ts normalizeNovaCliFlags` is the anti-corruption boundary from raw parser keys to one frozen camelCase CLI object; deleted dashed keys and raw `model`/`thinking` keys are not retained and legacy reads throw.

6. **Legacy adapter path aliases removed.** Resolved by RV-34: `services/adapter-registry.js` now accepts only canonical registry keys and active runtime tool paths. Removed aliases are absent from `listRegisteredAdapters()` and synchronously throw `UnknownAdapterError` during resolution.

7. **Make all user/config paths pass through named boundary helpers.** Resolved by named CLI prompt, delivery-lint Dockerfile, module/gate Buster payload, and swarm artifact helpers; Buster rejects unsafe path payloads before task execution. Relevant rows: `path-construction.md:P05-P001`, `P05-P002`, `P05-P003`, `P05-P005`, `OI39-P001`.
