## Execution Phases

1. **Boundary & Observability Hardening**
   - The system must be mathematically prevented from leaking secrets or swallowing deadlocks before any internal logic is touched. This phase seals the perimeter and establishes reliable terminal telemetry.
   - RV-02 (P0): Isolate verification DIs from live config. **Resolved.**
   - RV-03 (P0): Require secure Redis transport policy. **Resolved.**
   - RV-19 (P0): Redact contract diagnostics at source. **Resolved.**
   - OI-44 (High): Contract-invalid diagnostics redaction (covers unredacted plugin inputs). **Resolved.**
   - RV-20 (P0): Sanitize ACP transcript terminal results. **Resolved.**
   - RV-21 (P0): Add durable terminal-alert fallback for telemetry sink failure. **Resolved.**
   - RV-22 (P0): Add lock lease/staleness recovery and CRITICAL lock telemetry. **Resolved.**
   - RV-08 (P1): Add universal redaction contract for egress surfaces. **Resolved.**
   - OI-45 (Medium): Extend IO warnings to prompt appends. **Resolved.**
   - OI-47 (Medium): Centralize gateway-facing agent operations in common. **Resolved.**
   - RV-06 (P1): Harden raw prompt ingress. **Resolved.**
   - RV-07 (P1): Boundary-control Dockerfile/static validation paths. **Resolved.**
   - RV-04 (P1): Capability-gate Buster destructive/tool-heavy suites. **Resolved.**
2. **State Authority & Single Source of Truth**
   - With observability secured, the architecture must consolidate around a single source of truth. Legacy file-based states must be aggressively stripped of their routing and recovery authority.
   - RV-27 (P0): Reconcile module state authority (deprecate status.json as authority). **Resolved.**
   - RV-28 (P0): Define gate-status precedence. **Resolved.**
   - RV-29 (P0): Collapse active-session authority. **Resolved.**
   - RV-31 (P1): Remove status_json_path from Buster task contract. **Resolved.**
   - RV-30 (P1): Apply path-boundary helpers to all user/config paths. **Resolved.**
   - RV-32 (P2): Normalize CLI flag object. **Resolved.**
   - RV-33 (P2): Consolidate completion result wrappers. **Resolved.**
3. **Control Flow, Orchestration & Deadlines**
   - With state unambiguously defined, the fractured runners and fixed polling loops can be safely upgraded to event-driven architectures without risking state corruption.
   - RV-23 (P1): Introduce shared absolute deadline and abort-budget object. **Resolved.**
   - RV-11 (P0): Implement ACP event adapters for session state and transcript deltas. **Resolved.**
   - RV-12 (P0): Canonicalize ACP TranscriptDelta and MonitorState schemas. **Resolved.**
   - RV-14 (P1): Centralize ACP session termination result handling. **Resolved.**
   - RV-13 (P0): Make Generic GateRunner the sole runtime gate orchestration path. **Resolved.**
   - RV-16 (P1) & OI-46 (Low): Move approval waits from fixed polling to waitable/event signal flow. **Resolved.**
   - RV-24 (P1): Make rate-limit exhaustion observability non-optional. **Resolved.**
   - RV-25 (P1): Consolidate degraded/restored observability paths. **Resolved.**
4. **Deprecation & Structural Pruning**
   - The final phase deletes the compatibility shims, replaces obsolete concepts, and solidifies the dependency matrix.
   - RV-15 (P1): Delete wrapper-only compatibility shims after import migration. **Deferred.**
   - RV-26 (P2): Remove shim-only telemetry/redaction boundary layers. **Deferred.**
   - RV-05 (P1): Replace prompt shell snippets with typed completion APIs. **Resolved.**
   - RV-17 (P2): Replace fixed sleeps in retry/control paths with abortable wait utilities. **Resolved.**
   - RV-09 (P2): Consolidate Redis dependency loading. **Resolved.**
   - RV-34 (P3): Remove legacy adapter aliases. **Resolved.**
   - RV-10 (P2): Pin runtime/tool versions or declare supported matrix. **Deferred.**
   - RV-18 (P2): Update implementation maps after consolidation. **Resolved.**
