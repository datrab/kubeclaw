# V2 correction for CI2-TEARDOWN-01

Original V1 files and manifest remain unchanged. V2 adds one test-only lifetime helper and updates both test modules to enter that owner before setup. No production file, runtime, test execution or original deadline change.

The owner ties a dedicated AbortController to node:test's signal. Capture invocations and Nova gate executions receive it. The entire asynchronous body is observed immediately and joined during after-hook teardown, so exceptions, expected rejections and timeout continuation cannot race root removal. Runtimes register before start; their start attempt and idempotent stop are owned, and start sits inside try/finally. Capture runtime shutdown is registered under the same owner. Production stores in these tests are new and empty at start; no existing accepted jobs are introduced by setup.

On teardown, cancellation happens first and runtime shutdown starts to abort service work even when its HTTP client has stopped. The owner awaits body settlement, runtime shutdown and actual close events for every observed real spawn, bounded by a separate 10000 ms disposal deadline. No test/request/attempt deadline increases. Only full confirmation permits root removal. Rejected shutdown or disposal timeout retains the root and throws CLUSTER_TEST_FILES_RETAINED with its path/cause.

Child observation transparently delegates unchanged command, arguments and options to the original child_process.spawn, returning the original child and observing its real close. There are no simulated command responses, process signals or close events. Production invoker runProcessInput still owns cancellation/disposal; the observer does not substitute its executor. The instrumentation exists only to prevent treating a rejected operation with unconfirmed cleanup as proof that files are safe to remove. The hook restores in finally after either confirmed cleanup or explicit retained-root failure.

The RuntimeSecurity V3 package command and architecture content are preserved; CI2 additions are appended against that snapshot in before-v2. Control source hashes were refreshed against current integrated source and each old anchor remains unique. Case matrix and intended mutation failures remain V1's original scope (14 capture cases and four profile/capability cases × three authority modes). Runtime execution and fresh independent review remain outstanding.
