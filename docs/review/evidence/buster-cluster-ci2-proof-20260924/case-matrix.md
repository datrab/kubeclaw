# CI2 capture and production-route proof draft

Private source package only; no runtime, build, live source change, cluster access or claim of passing tests. Original tests, deadlines and command members are retained. Freeze inventory is `manifest.json`; only existing-file overlaps are package.json and the cluster configuration architecture page. Seven proposed semantic controls are bound to current production hashes in `semantic-control-specs.json`. Their hooks must run in the same actual tool/source binding as baseline, and expected *particular* failure must be reviewed, not just nonzero exit.

Sequence: original capture succeeds through actual executable; mutate component-file bytes or mutable caller-owned nested input; old consumer succeeds again with same request and new command trace; file mode also constructs another consumer from the old snapshot and expects success; fresh snapshot/constructor enforces changed profile on the same request. The local executable reads stdin, records PID/argv/input, mutates private lease state and emits modeled API JSON. No spawn mocking, custom invoker.execute seam, forwarding replacement or real external cluster is used.

## CI2-PRODUCTION-ROUTE — four profile/capability cases, each with three modes

Two full authored component profiles vary installation namespace binding, namespace prefix, API group/version, runner service account, registry endpoint/repository and hostname suffix. Each invokes Kubernetes fixture or Tailscale exposure through:

`createProductionNovaTestGate.execute → signed archived source → HTTP → loadProductionBusterRemotePlanRuntime → real service/store → prepared execution → discovered provider child → context.invoke IPC → real cluster capability → actual local executable`.

Native preparation identity/publication is explicitly modeled by the existing adapter. The decoder/service/capability forwarding being proved has no replacement. Configuration is loaded using the actual swarm bundle loader. The only API simulation is the clearly declared local command program.

- Allowed: provider result must pass; observed command PID differs from parent; real auth argv has selected API group and binding namespace. Kubernetes lease dry-run/apply inputs must contain selected API version, full runner subject and immutable registry image; actual manifest application contains that registry. Exposure must issue patch and the genuine provider verifies its returned hostname.
- Missing grant: exact TEST_PROVIDER_CAPABILITY_DENIED in the imported persisted attempt, no command increase despite complete policy.
- Disabled route: exact BUSTER_REMOTE_CAPABILITY_DENIED at admission, no command increase despite granted provider and complete component.

Each runtime stops in finally; temporary files are owned by the test. New test deadlines are 15 s capture and 60 s per production case, with unchanged request readiness 1000 ms, plan attempt 20000 ms and existing original remote-gate 30000 ms patterns. No original deadline is changed.

## DOC and acceptance boundary

The staged architecture delta explains both proof routes and their modeled boundaries, names the maintained gate, and explicitly does not equate source coverage with executed evidence or full CONFIG/live/native closure. Root must integrate only after fresh source review, preserve failed runs, execute maintained baseline and intended-failure controls, and obtain independent raw-evidence/DOC acceptance. This draft does not close CI2 yet.
