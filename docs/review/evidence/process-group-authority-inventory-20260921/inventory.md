# Process-group authority inventory — source only

This record extends F1 and does not claim migration, runtime safety or acceptance. All five inspected sources are frozen in source-identities.json. Production files were not changed.

The Foundation captureLinuxProcessGroup function owns an unconditional 250 ms /proc scan deadline. Its production callers are Buster ProcessInputLifecycle, Nova SourceProcessLifecycle and the common command-runner CommandProcessGroup. Making this required configuration only at the Buster call would leave two effective consumers unauthoritative. A shared required API must propagate the appropriate single selected owner value to every caller, with validation before spawn or scan effects and explicit full test profiles.

Buster cleanup/grace/poll are already explicit selected execution.processInput settings. Nova source cleanup still authors 1500/250/10 ms in code. The command runner receives graceMs from its caller but separately authors a 1000 ms acknowledgement budget and 10 ms polling. These are distinct live operational settings, not Linux protocol constants. Command-runner signal suppression catches all errors, whereas the Buster signal method suppresses only ESRCH; this is a separate quality issue, not silently fixed by inventory.

The Nova lint plugin has another captureLinuxProcessGroup implementation. It is not a direct Foundation caller: it permits an already-gone group to return undefined, has no capture deadline, batches asynchronous member reads in groups of 64 and polls every 10 ms. Do not mechanically replace it without proving its actual termination callers, namespace behavior and original error contracts. Batch size and polling are further policy authors; Linux status field names and zombie/exit state interpretation are protocol rules.

A source-reachable Nova error-retention concern also needs independent review: a timed KILL error is appended to signalFailures, but when actual close and group acknowledgement subsequently resolve, #finish returns without checking that list. This could discard an observed signal error. No runtime reproduction is claimed here. The first TERM throws directly into the catch before the Promise.race/native-close wait is installed. The catch issues KILL, destroys parent pipes and rejects without awaiting actual close. sourceGit forwards that rejection as CLEANUP_UNCONFIRMED, so this path does not claim successful cleanup; it can settle before the process ends. This ownership path also requires examination against its existing contract. These are not evidence that Buster's recently fixed behavior already applies to Nova.

Completion requires normal-path loader/owner propagation for every selected setting, missing/invalid rejection, two real behavior profiles, restored-literal controls, original process/namespace/descendant tests, removal of replaced authors and operator documentation. Any remaining separate lint implementation must be justified by an explicit contract or correctly replaced; an inventory alone closes none of CONFIG.
