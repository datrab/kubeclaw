## Implementation

The strict author schema and loader now require the resource-policy object.
Control and Worker capture deeply frozen policy snapshots. `prismNativeAttempt`
requires the policy as its fourth argument; `prismNativePolicy` and its three
environment reads/defaults are removed. All 33 current producer calls explicitly
provide a policy; test/integration producers use a shared fixture that invokes
the original author loader, not copied defaults. Production Control passes its
startup snapshot directly.

`prismAttemptResourceLimits` contains the existing admission semantics and is
called by the real supervisor execution path: new budgets must fit the loaded
policy, recovered accepted budgets retain their prior meaning, and all three
budgets must still be requested. It maps V3 maximum-memory/task fields to actual
process-limit names without changing their units. The new small pool-consistency
function compares only memory bytes and Linux tasks; supervisor composition calls
it after reading the trusted root-owned pool policy. It does not infer aggregate
CPU-time capacity from CPU quota or period. Host/kernel admission remains separate.

Helm validates the required nested object with safe-integer bounds, transports
identical authored bytes to both roles, and rejects competing Control/Worker
values. Resource limits are not constrained to the Node timer ceiling. Existing
transport settings retain their original bounds.
