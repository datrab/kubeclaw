## Material findings

### FAPR-01 — Native evidence pathname mistaken for review-policy consumer

**High; incorrect field activation classification.**
The final map assigns these original IDs to `review-quality-module`, classes[M]:

- `DLV-PRISM-BACKUP-CONTROLLER-TIMEZONE`
- `DLV-NATIVE-OPENCLAW-AGENTS-DEFAULTS-TIMEOUTSECONDS`

Their decisionBasis claims actual parsed/frozen review policy. Their actual
sources are pinned native packages under `docs/review/evidence/...`, not the
Nova review plugin. The preliminary builder's `if '/review/' in p` branch
explains the collision; it survives in the authoritative final map.

The Cron field's pinned `parser.go:94` selects `time.Local` absent explicit TZ;
its productive chain is Chart CronJob/controller/cron scheduling. Its original
currentScope itself specifies S future CronJob generation and preserved R Jobs/
deadlines. A new project review module cannot change that physical scheduler's
timezone. The OpenClaw resolver reads actual `cfg.agents.defaults.timeoutSeconds`
and per-run overrides, passing the selected timer to reply/run execution; it is
a runtime run/deadline contract, not a reviewer quality field. Its R ceiling/
eligible run projection must be resolved at that real consumer.

**Fix:** correct both final field rows and their patterns/contracts with explicit
source-specific scheduler/runtime boundaries and unchanged existing authors/
original cases. Audit all pinned evidence source rows for this path collision;
do not classify native semantics from the location of the source archive.

**Fix:** add exact existing original and supplemental case IDs or immutable
