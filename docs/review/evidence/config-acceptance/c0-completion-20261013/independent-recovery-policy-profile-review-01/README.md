## Findings

### WCR05-R01 — task path schema excludes timestamp digits, not NUL

**Material schema contradiction.** `recovery-policy-profile-01/schemas/recovery-task.schema.json:54,72` stores JSON `"^/backups/litellm/backup-[^/\\\\u0000]*$"`. After JSON decoding, the regexp character class contains a doubled backslash: it excludes `/`, literal backslash, `u`, and `0`; it does not exclude U+0000. Both restore and migrate reject authentic published names containing `0` (the actual script57–92 generates `.incomplete-$(date -u +%Y%m%dT%H%M%SZ)-XXXXXXXX` and publishes `backup-...`, including `backup-202610...`). Valid random suffixes containing `u` are also spuriously rejected. A NUL-containing JSON task has no corresponding safe argv/path receiver. This contradicts preserving original direct-child argv and rejecting invalid task data before effect.

The existing task control at collector40 uses only `/backups/litellm/backup-fixture-A`; it passes but does not exercise actual publication grammar or NUL. This finding is static regexp/JSON inspection, not an additional unapproved test run.

**Required additive correction:** define the intended direct-child character grammar with correct JSON/regexp escaping; explicitly exclude NUL and preserve real timestamp/random publication names. Extend the existing narrow task-schema controls with a real publication-shaped positive containing `0`/`u`, NUL rejection, nested/escaping rejection and original arity/version negatives. Preserve current01 bytes and receipt. No task reset/new policy knob is needed.

### WCR05-R02 — retained aggregate enters signed Bash arithmetic before range validation

**Material numeric receiving gap.** Actual `scripts/postgresql-recovery.sh:59–63` accepts any-length `du --summarize --bytes` decimal (`^[0-9]+$`) and immediately computes `retained - used - reserve`. The proposed ABI budget128–131 preserves this exact allocation formula but bounds only policy inputs to13 digits/native signed64. It does not define validation of the independently measured aggregate before conversion/subtraction. Old/incomplete/imported history, metadata accounting, an out-of-range tool result or unsupported output can exceed policy's numeric domain; bounding configured retained bytes does not bound this external datum. Signed arithmetic wrap or leading-zero base interpretation must not create fresh positive allowance. Current simple `allowance > 0` runs too late to establish fail-closed behavior for such input.

**Required additive correction:** require successful authentic accounting capture, canonical nonnegative decimal validation and native representability before arithmetic; compare `used` against selected retained capacity without overflowing conversion, reject over-capacity before subtraction, and then prove nonnegative checked `retained-used-reserve` and block conversion. Keep all original completed/incomplete bytes, fail closed without deleting/resetting history, and retain the exact source/tool/PV authority. Add finite narrow definition oracles for zero, exact retained/reserve boundary, leading zeros/malformed output and greater-than-native/retained aggregate.
