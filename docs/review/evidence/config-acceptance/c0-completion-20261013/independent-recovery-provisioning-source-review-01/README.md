## Provisioning: per-function facts that held

- `deploy.sh:968` selects `$VALUES_DIR/setup-secrets.sh` and requires executable
  permission; deploy exports namespace and PostgreSQL/LiteLLM switches125–127.
  Direct helper invocation remains supported. Helper empty-or-unset ENV defaults
  and permissive boolish normalization are current deployment/provisioning
  settings, not strict future validation or immutable module-generation capture.
- Auto/interactive/true requires readable/writable `/dev/tty`; noninteractive/false
  disables prompts; unknown modes reject. Most incomplete target Secrets warn
  and return under noninteractive operation. Object/key presence checks and partial
  returns do not prove usable credentials or an accepted deployment.
- Shared-secret precedence is existing no-overwrite target/key handling, SOPS file,
  source copy, interactive creation, then warnings. It is not every secret's
  universal precedence. Redis/PostgreSQL/Google/git have their own target/copy/
  prompt paths; GHCR has its own overwrite prompt path. The attestation helper may
  replace an incomplete pair and generate Ed25519 noninteractively. The fixture
  helper reuses an existing object without validating `proof` shape, otherwise
  generates32 raw bytes. These exceptions are explicitly retained.
- SOPS named keys and Stitch aliases are actual source reads; Prism's `||`
  generation fallback can run on extraction/decrypt failure, not only a proven
  absent field. It is historical behavior, not accepted CONFIG fallback removal.
  Generic generation is32 entropy bytes as64 hex characters or base64-encoded
  urandom bytes, distinct from fixture raw32 and Ops bearer48-byte generation.
- Source copy checks NotFound separately from other API errors, then copies the
  current YAML object with namespace substitution/apply. This is no immutable
  revision capture. Key reads, errors in subprocess/process-substitution paths,
  warnings and return handling must retain their individual current boundaries;
  a successful helper exit must not be generalized to complete credential readiness.
- Shared LiteLLM master and PostgreSQL password feed later LiteLLM creation/patch
  when available; an existing/copied complete LiteLLM Secret is not automatically
  synchronized to them. Disabled PostgreSQL takes explicit external DATABASE_URL
  input. The later namespace rewrite uses unparsed global grep/sed replacement
  and reapplies actual Secret data, potentially beyond hostname-only text. It is
  mutable provisioning, not a guaranteed credential-preserving URI projection.
- OAuth false disables creation; existing target/key handling precedes complete
  ENV pair, source copy and interactive prompts. Its namespace/name and provider
  keys are separate from application scopes. None establishes provider grants,
  token usability, original revision availability or recovery credential closure.
