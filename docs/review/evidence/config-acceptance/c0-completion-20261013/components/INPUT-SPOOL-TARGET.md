## Source boundary and ownership

`server/control-context.ts:16` constructs one `ContentAddressedArtifactStore` from the selected Control `artifactRoot`. Five productive writers share that physical store: `control/native-operation.ts:14` (JSON engine input), `server/project-routes.ts:92` (architecture), `server/baseline-route.ts:91` (assembled baseline), `server/corpus-routes.ts:47` (decoded corpus input), `server/internal-artifacts.ts:50` (worker artifacts). Integration fixture stores are not installed instances. All five must participate in aggregate capacity accounting; a native-only ledger cannot establish shared physical headroom.

`storage/artifacts.ts:43` owns content before awaiting, computes SHA256, creates/syncs directories, writes/fsyncs a unique pending inode, hard-links the final object, verifies an existing final object, syncs directories and removes/syncs pending. Duplicate digest is **not** zero-write current behavior. `get` verifies bytes, not quota or provenance. `native-operation-store.ts` already supplies PostgreSQL transaction/advisory lock and durable original key/envelope/result; this is the justified composition point, not a new configserver.

Sole policy author: existing `config/services/prism.config.json#/profiles/<selected>/artifactStore` (proposed new fields under existing owner). `CMP-prism-control-artifactRoot` remains sole editable locator author; physical store identity/grant is authenticated Delivery output, not another path writer. Proposed settings: `maximumObjectBytes`, `maximumLogicalBytes`, `maximumReferences`, `maximumPendingBytes`, `maximumPendingObjects`, `maximumUniqueContentBytes`, `maximumUniqueObjects`, `maximumLedgerBytes`. Each is a required positive safe integer; bytes/counts do not share units. Byte arithmetic uses checked integer addition/multiplication; exact intermediate overflow rejects, never wraps. Numeric policy values are operator choices within authenticated provider constraints, not portable disk capacities. Retention remains existing original owner/rights/operation obligations; these fields cannot expire live references.

The grant is an immutable authenticated generated record, not task data: store instance ID, canonical physical volume/provider identity, selected policy digest/generation, authenticated capacity observation revision, allocation-unit bytes, allocatable physical bytes/inodes, excluded reserve bytes/inodes, ledger provider identity/allocatable bytes, allowed principals and writer classes. Required provenance/signature references use the existing trust producer; the external provider contract must actually authenticate this tuple. No default `statfs`, PVC request or corpus/upload limit can stand in for it. Fresh admission requires the exact original grant; historical recovery resolves only retained original grant, never latest capacity.

## Exact accounting and admission relationships

A store closure enumerates every existing final inode, pending inode, directory and live reference (including pre-migration content) or blocks all new writes. Observe allocated blocks/inodes from the authenticated provider, not byte length alone. File sparse/compression/CoW behavior is provider-specific; unsupported overcommit disables admission. Capacity guarantee must be enforced by provider quota/exclusive allocation: an instantaneous free-space sample is not a reservation.

Charges have separate checked dimensions: logical bytes per live reference (including shared content), reference count, pending owned byte length/object count, unique final content length/object count, ledger canonical bytes, physical allocated data/metadata bytes and inodes. Directory creation is included before the first `mkdir`. Existing content counts once physically but each admitted reference counts logically. Reservation worst-case includes owned pending allocation **plus** final object where publication can allocate separately, required directory/inode/metadata allocation and ledger reservation. For current same-filesystem hard-link algorithm final/pending data are one inode; conservative double-charge is allowed only as a declared provider reservation strategy, not a claim of two physical copies. Actual retained physical charge is read back after confirmation.

For each policy dimension D, `charged(D)+reserved(D)+candidate(D)<=selectedLimit(D)`. For physical bytes/inodes, total allocation/reservations plus provider reserve stays <= authenticated quota. Ledger capacity includes the new record, ownership/ref indices, state transitions and bounded retained diagnostics, using exact canonical serialization/provider allocation. Policy limits do not promise feasibility; reject candidate before any write when any provider dimension cannot reserve. Grant omission/revision mismatch/unknown historical closure reject `PRISM_ARTIFACT_STORE_GRANT_REQUIRED`, `PRISM_ARTIFACT_STORE_BINDING_CONFLICT`, `PRISM_ARTIFACT_STORE_HISTORY_REQUIRED` respectively. Exhaustion identifies exact dimension in `PRISM_ARTIFACT_STORE_CAPACITY:<dimension>`.

Input size also remains subject to accepted native envelope/worker limits. Those request limits bound individual consumers and are additional predicates, never substitutes for aggregate store accounting.

## Durable state machine and failure boundary

Pure owned-byte hash/length precedes IO. Within existing operation transaction and consistent store-object lock order, lookup original key first. Existing terminal result hydrates original result without new spool/reference/reservation. Different input/request/provenance tuple rejects original idempotency conflict before IO. New admission atomically persists original module closure, grant, descriptor, exact bytes digest/length and all reservations with operation envelope. Store-wide object/reference locking serializes shared-content ownership across all writer classes. Existing pending operation does not acquire new latest policy or restart deadline/claim.

States: `reserved -> materializing -> ready -> retained -> release-pending -> released`; `materializing` may enter `quarantined` on unverified/corrupt/uncertain filesystem state. Before `materializing`, trusted immutable original runtime/code verification must succeed; otherwise no new directory/pending/data write. An owned reservation alone is not readiness. Writer publishes only reserved owned bytes into selected original physical store; durable checksum/size/allocated-state readback precedes `ready`, which precedes dispatch. Failures preserve charged/reserved uncertainty and never claim rollback from attempted unlink. Error diagnostics remain bounded within reserved ledger capacity.

Crash after transaction before IO resumes original reservation. Crash during pending write accounts observed/original worst-case allocation and reconciles exact owned pending inode without arbitrary directory sweeps. Crash after link before ready verifies original final/pending ownership/durability, then advances or blocks. Crash after ready reuses verified input without current write-first `put`. Post-dispatch uncertainty follows original fences; no reexecution on a storage timeout. Reference release is durable before deleting last unretained owned object, but deletion confirmation is required before physical charge release. Shared content cannot be deleted while any live/retained reference exists. Cleanup uses original grant, reference and retention policy, not B.

## Activation and migration

Physical store/root/provider/trust/retention are stable service/run closure; tuning may select B only for a genuinely new operation/module with a new original admission. A and B charges coexist in one authenticated aggregate store ledger, neither reset nor independently overpromise shared capacity. Fixed Eval captures one generation and uses retained original grant. C3 adds required owner decoder/all five writer composition; C5 adds pre-effect binding/retained original provenance. No D18 Job change belongs in this CONFIG package.

Legacy objects/operations require authenticated import of original ownership, retention, physical allocation and original policy, or read-only hydration/quarantine; latest policy must not synthesize missing history. Missing deployment observation is an external fixture prerequisite, not an excuse to leave the target admission algorithm undefined.
