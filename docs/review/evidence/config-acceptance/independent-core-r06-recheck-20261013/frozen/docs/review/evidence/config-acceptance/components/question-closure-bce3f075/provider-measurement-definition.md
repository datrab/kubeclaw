# Provider data provenance, not settings

The current zeros used in `Math.max` are identities for merging absent child CPU/memory fields, not observed usage. The child currently reports its own `process.resourceUsage` CPU and sampled `process.memoryUsage().rss` peak; it never reports `maximumProcesses`. Parent procfs samples an owned tree. Neither a missing child field nor a disappeared PID establishes a zero measurement. The seeded one is a lower-bound root count following spawn, not evidence that the process remains live.

Real `processFacts` returns `{0,0,1}` for a genuinely vanished child; the current source control records this. IO errors fail, but ENOENT/ESRCH skip entries. Close prevents PID reuse, preserving observed values rather than sampling unrelated future processes. No cadence or zero toggle may waive unavailable observations.

## Concrete target data transition

1. Before constructing/spawning a session, create an attempt-owned launch receipt under the **existing captured attempt metadata quota**, linked to full envelope/claim/source/policy generation. A no-launch transition is valid only before any spawn ownership is acquired. Record a fresh session identity and boot/PID-start identity once acquired; no fake PID ownership from numeric PID alone.
2. The loader owns this receipt even if post-spawn cancellation or initialization rejects before `RunnerProviderState.instance` assignment. Its rejection/disposal result carries the same snapshot/receipt reference to runner state; no lost launched-instance state is replaced by `{0,0,0}`.
3. Each metric snapshot carries internal provenance: `not-launched`, `observed`, `partial` or `unavailable`, source (`child-own-process`, `procfs-owned-tree`, or confirmed native disposal), value only where actually measured, observation timestamp and owned session identity. CPU fields are finite nonnegative source measurements; conversion microseconds/1000 then ceiling must remain safe integer. Bytes/process counts are nonnegative exact safe integers. Child fields are validated before max; strings, NaN/Infinity, negative/unsafe values reject. Missing fields are not zero observations.
4. Retain monotonic CPU and peaks only from this session's measurements. An incomplete sample may be retained as a known lower bound, not used to certify a requested whole-tree budget. Document source coverage; do not assert sampled instantaneous memory is a universal RSS peak. Disappeared entries remain partial/unavailable unless confirmed final owned measurement closes the coverage gap.
5. V1 Buster `measure` returns the numeric batch only for a valid complete measurement under its declared execution contract. For unavailable/partial requested measurements it throws a typed measurement error. **Reuse the existing** `attempt-executor.ts:446–450/555–558` catch-to-undefined and `resource-accounting.ts:16–26` strict V1 rejection path (`WORKER_RESOURCE_MEASUREMENT_INVALID`); do not invent a permissive new V1 observation toggle or relabel as unrequested V2 budgets. A genuine proven no-launch path may return zero, but its prepare/cancel fault remains and no successful launched work is claimed.
6. Once actual closure/disposal is confirmed, preserve final owned snapshot and do not sample reused PID. A cleanup recovery session has a fresh session/claim; combine CPU once, memory/process maxima as today, preserving provenance and missing-coverage error. `WeakSet` bookkeeping prevents double-accounting, not lost-session accounting.
7. Persist/recover the receipt and referenced snapshot under existing metadata/total ceilings, bound before effect and checked before result; fixed Eval uses genuine same-source measurements, never injected numeric counters. A failed observation cannot promote a successful budget receipt.

This is a proposed correction to generated data/ownership semantics, **not implemented** and not a new operator policy. Real sandbox/provider cases require the absent compiled `foundation/isolation/plugin-sandbox` build in a disposable approved stand. Actual native observations are a future execution prerequisite, not invented facts. Registered package digest/snapshot, sandbox and current provider child must be used; no replacement executable, sampler or mock counters.

Cases `QC-BUSTER-PROVIDER-MEASUREMENT-FALLBACKS-REAL-PROVENANCE` and `...-RECOVERY-EVAL` enumerate successful, short-lived, no-launch, post-spawn load cancellation, failed initialization, malformed/missing child fields, cleanup/session reuse and crash recovery. Their exact planned harness invocation and real boundaries are in `question-case-specs.json`.
