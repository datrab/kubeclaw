# Independent review of private provider child session draft

Verdict: no concrete semantic regression found in the inspected private refactor. This is source review only, not runtime, lint or integration acceptance. The reviewer did not author the draft. Both before/draft identities match their declared hashes; [comparison evidence](../../evidence/independent-provider-child-session-simplicity-20260921/source-comparison.json) also binds the patch and draft README. No live source was edited and no child or test was executed.

The reviewed draft SHA-256 is `da937f52ae501a769e5a59ad67dc5a1ea96ce45352556815e2789e1bd14341e9`; its before hash is `5dd41b92245c36b8e4d1d63d8a14f95f8647fda040ba2c3c60e20a088becfa50`.

| Boundary | Source comparison |
| --- | --- |
| Startup | One session is instantiated at module evaluation. Its field initialization creates pending state and the AbortController before installing the permanent TERM handler; RSS sampling and readline follow, as before. Console reassignment remains after input listener registration. No added await or intentional event-loop yield separates these steps. |
| Concurrent receives | Each line independently starts an async receive with its own rejection handler. Awaiting provider execution does not serialize later capability responses or abort messages behind it. Introducing a sequential input queue would change this crucial property. |
| Binding | Private receive uses a lexical arrow; context invoke explicitly binds the private RPC method to the session. Provider execute/cleanup remain property calls on the provider instance, preserving provider `this`. Factory invocation remains a plain local function call. Frozen context still refers to the same controller. |
| RPC settlement | Sequence, IDs, combined controller/caller signals, already-aborted rejection, pending registration before send, once-only abort listener, pending deletion and capability-abort message remain equivalent. Successful/error replies delete and detach before settling; unknown/late replies remain ignored. This refactor does not add a new protocol state machine or claim to fix inherited malformed-command/concurrent-initialize behavior. |
| TERM and IPC abort | Both target the same controller. The TERM listener stays installed rather than becoming once-only; repeat abort calls are idempotent at the AbortController. No early exit bypass is introduced. Parent stop bounds remain responsible for forced cessation. |
| Completion/cleanup | Execute checks for unresolved capabilities before emitting result. Cleanup awaits the provider cleanup method, emits cleanup-result, then clears sampling and closes readline. Error handling still sends error/resources, schedules finish, and sets exitCode=1 before the scheduled exit callback reads it. The draft does not add an unconditional pending-RPC drain that the original lacked. |
| Resources | Initial RSS observation, 10 ms maximum-RSS sampling, process CPU conversion from microseconds to milliseconds, sample timer lifetime and resource message shapes are retained. Sampling is still approximate and its cadence remains an open D17 policy-author issue. |
| Console/loading | Dynamic import, four console assignments, JSON protocol writes and binary log base64 conversion remain explicit. Provider import-time logs still pass through the same console routing. The refactor does not conceal or remove architectural boundary findings. |

The class gives the child process one cohesive state owner without a new framework or unrelated behavior. Five mutable module-state declarations move into that owner. No lint execution was performed to establish that those findings are gone, and the seven separate boundary findings explicitly remain open. No rule change or suppression is part of the reviewed patch.
