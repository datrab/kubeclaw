# CI2 ownership helper behavior gate

Prepared private source only; not executed. The reviewed V2 helper remains unchanged. This gate adds three actual isolated `node --test` subprocess scenarios. An outer maintained test asserts concrete observed effects and exact nested error chains, not just nonzero exit codes. `npm run verify:buster:cluster-ownership` is the new standalone command.

Each scenario starts a genuine Node child that remains alive behind a file barrier. The nested test uses the actual ownedClusterTest helper. A deliberately modeled runtime tests its start/stop contract; only its explicit stop success/rejection/barrier behavior is modeled. The helper's observer, real child spawn/close, node:test timeout and filesystem operations are not replaced. Child close records whether the root still exists, providing an observation before any promise-continuation deletion.

- OWN-TIMEOUT-CLEAN: actual 2000 ms node:test timeout while body and real child remain active. Parent waits for abort/stop entry, confirms root retention, releases body while stop and child remain held, releases stop while child remains held, then releases child. Genuine close must report root still present; completed nested process must report the original timeout and leave root removed. No helper error may replace the timeout.
- OWN-STOP-FAILURE: actual body rejects OWN_BODY_SENTINEL, registered stop rejects OWN_STOP_SENTINEL. The reporter serializes node:test's original error/cause/AggregateError tree. Parent requires CLUSTER_TEST_FILES_RETAINED → CLUSTER_TEST_SHUTDOWN_FAILED → OWN_STOP_SENTINEL and the body diagnostic, with root retained before and after exact-owned child release/close.
- OWN-DISPOSAL-TIMEOUT-LATE: body/runtime settle but actual child remains held past the unchanged 10000 ms helper disposal deadline. Parent requires the exact retained-root → CLUSTER_TEST_DISPOSAL_UNCONFIRMED chain before releasing the child. Root must remain present at close and after the complete nested process exits, excluding a delayed deletion continuation.

Nested intentional failures must exit 1, never success or signal termination. No unhandled rejection/uncaught exception is allowed. Reporter output is parsed strictly once complete. Event and reporter logs live outside the helper's root so its successful deletion does not erase observations. Parent owns a dedicated process group with a 25-second watchdog and a 35-second outer test bound; on an unexpected failure only that group is signaled and evidence remains. Helper's original 10-second timeout is not shortened or relaxed.

`controls.json` prepares two isolated controls: premature root deletion and late inner deletion after timeout. Each must fail its intended filesystem oracle with genuine child activity, with unchanged baseline tests. Controls are not executed or claimed passing here. Full original CI2 capture/service cases and policy controls remain required separately; this gate cannot replace those behaviors and proves no production ownership guarantee.

The nested test reporter's actual failure serialization and all expected failure modes require execution; source inspection is not a passing gate. Any mismatch must be diagnosed in raw logs rather than broadening expected error patterns or swallowing body/stop errors.
