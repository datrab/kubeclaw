# Isolate the registered runtime stop failure

Observed retained Ownership2 evidence shows genuine node:test reports only the original OWN_BODY_SENTINEL failure when both the body and its after hook fail. The event file proves body-rejecting, stop-entered and the genuine child receiving the stop request. It contains no public hook cause tree. This is not evidence for the required concrete stop-error propagation, and no such pass is claimed. Raw observed logs are preserved in observed-ownership2/.

Root explicitly requested the smallest genuine-behavior correction and allowed isolating stop failure with a successfully settled body if documented as a scope decision. This proposal changes OWN-STOP-FAILURE's body from rejection to successful settlement. The registered runtime still rejects the same OWN_STOP_SENTINEL while owning the same held real child. The outer gate must now observe successful body settlement plus the exact FILES_RETAINED → SHUTDOWN_FAILED → OWN_STOP_SENTINEL cause chain, root retained before and after child close, and no unhandled rejection. It does not accept the old primary-body-only report.

This is an explicit scenario/oracle clarification, not an assertion that all old oracles are unchanged: simultaneous body rejection is no longer the trigger in this one gate case. The requested behavioral gate permits body settling/rejecting, and this case isolates the stop-error path that Node can publicly report. It does not prove that Node publicly reports both simultaneous failures; the preserved failed attempt proves the opposite on the actual runtime. If independent review requires the simultaneous-rejection case as an additional obligation, it remains open rather than silently being declared covered by this isolated case.

The two passing timeout-clean and disposal-timeout-late cases, their assertions, all timeouts, helper implementation, real child/IPC barriers, strict rejection handling and terminal-generation guard remain unchanged. No runtime or live write was performed. Fresh source review and rerun are required.
