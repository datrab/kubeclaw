# RuntimeSecurity lint correction: behavior and boundaries

Private source-only proposal against the actual integrated V3. No runtime or lint execution, no test/regression edits, no live-source writes. Active root runtime source HOLD is preserved.

`kubernetesCredentialEnvironment()` extracts exactly the four credential/transport reads already owned by the approved `kubernetes-fixture-runtime.ts` infrastructure boundary: HOME, KUBECONFIG, KUBERNETES_SERVICE_HOST and KUBERNETES_SERVICE_PORT. Both kubectl callers read the same inputs at the same per-command point; returned properties and undefined-value semantics are unchanged. Each caller continues to provide its own explicit PATH, and RuntimeSecurity retains deterministic LANG/LC_ALL. No component policy is read from environment and no fallback is added. Existing environment-boundary lint rules remain untouched.

Architectural tradeoff requiring review: RuntimeSecurity imports this cohesive transport function from the existing Kubernetes fixture adapter module, so its runtime module graph gains that adapter's dependencies. The function imports no invoker instance and performs no work at import time itself; its returned values belong to the same kubectl credential transport shared by both capabilities. It is not a general utilities collection. A dedicated transport module with relocated ENV-boundary rules could remove the module coupling but would be a separate deliberate boundary change, not silently introduced merely to silence lint.

`runtimeSecuritySnapshot()` extracts the original status object validation, short-circuit namespace/spec ownership check, and nullable snapshot shape projection verbatim. `observationMatches()` extracts the original conjunction in the same order: phase, manifest digest, immutable image, findings shape, positive safe pod/service counts, exact accounting, current clock freshness and result-digest shape. The predicate returns a type guard only for TypeScript narrowing; it introduces no admission path. The computed digest mismatch error remains in the original invoking loop after that conjunction. The original conjunction is archived in `extracted-before.txt`.

Request validation, manifest reading, timeout calculation, poll timing, cancellation, command byte accounting, output-cause priority, digest computation and returned result construction remain in their original order. No deadline, error oracle, capability check or cleanup behavior changes. Unbounded manifest reading and abort-before-close ownership stay open.

The two production changes require fresh source review, canonical types/lint and affected runtime regression on the integrated corrected stand. Existing mutation specs referencing RuntimeSecurity need their source digest updated, with unchanged intended mutations checked for unique anchors. No pass is claimed here.
