# RuntimeSecurity invoker policy — private design before implementation

Status: source-derived proposal for Root/Huygens review. No implementation, integration, runtime, Helm, type or lint execution. The active Cluster runtime source remains frozen. This is the next portion of D17, not an exception or closure of other CONFIG obligations.

## Single authority and cutover

Add one REQUIRED object `settings.clusterInvokers.runtimeSecurity` to the existing complete Buster component. All eight fields in ownership.json are explicit in both the canonical and selected full runtime profile; no property merging, schema defaults, ENV fallback or optional constructor policy. Their initial values reproduce current entrypoint/consumer values. Shared executable, API group and projected namespace continue to come from the existing cluster shared policy and namespace binding. Do not introduce a second endpoint, registry or namespace setting. API version is not consumed by this invoker's group-qualified resource lookup; do not invent a version argument or alter resource discovery.

Normal route gating remains `allowedCapabilities.has('kubernetes.runtime-security')` and the unchanged capability factory add/required boundary. Replace the source-object author in capabilitySources with an enabled boolean. Reject the old runtime JSON `kubernetesRuntimeSecurity` key by presence, including empty, null, malformed and exactly equal legacy profiles, before runtime registry/store effects. No new ENV key is introduced; shared retired ENV checks remain. Component settings remain required even when this capability is disabled. External namespace binding may be absent when every cluster route is disabled; supplied malformed bindings still reject, enabled RuntimeSecurity requires a real namespace binding. Production must not enable the route because a component object exists.

Direct constructors validate and capture the full explicit settings before realpath/access/spawn or manifest reads, copying prefix/PATH lists. The old constructor currently performs realpath/access before validation; this ordering is an actual defect of missing-input admission to fix, not a claim already satisfied. Freshness's exported helper gains a required explicit future-skew argument, and all original direct callers retain their effective 5000 ms value. No helper fills omitted policy.

## Effective policy coverage

ownership.json is the machine-readable eight-field mapping. In addition to the obvious five runtime-JSON fields, this cut includes the actual future-skew 5000 ms, diagnostic 1024 code units and subprocess PATH authors. Shared component metadata continues to resolve the initial executable against the captured physical generation. Search-path entries are explicit absolute directories; no runtime-JSON relative-root fallback.

Selected policy differs from these unchanged request/protocol rules:
- Request `timeoutMs` is capped by the selected maximum. An omitted/noninteger request currently uses that selected maximum; this request behavior introduces no independent numeric operator default. The provider's separate 120000 ms request default and schema bounds 1000..300000 are an explicitly OPEN provider-owner migration, not permission to retain it indefinitely.
- Lease name 253, namespace 63, manifest digest 71 and generic text 2048/path 4096 limits are existing input/identifier contracts. SHA-256, exact accounting, overflow sentinel, positive observed pod/service counts and namespace/image/digest association are protocol/security checks, not newly selectable admission bypasses.
- `LANG`/`LC_ALL=C.UTF-8` enforce deterministic CLI decoding; HOME/KUBECONFIG/Kubernetes service host/port remain credential/transport inputs. No secret values move into the component or evidence.
- Controller refresh 5 seconds and controller finding-capacity policy have their own role owner and remain open; host observation age/skew do not re-author them.
- Manifest hashing currently uses readFileSync without a manifest-size admission budget. This is a concrete remaining resource gap, not covered by output bytes; adding a new limit needs an explicit scope/value decision and is not disguised as preservation.
- The current local kubectl wrapper can settle on abort/output error before actual child close and has no detached group lifecycle. This proposal does not silently replace it or claim native/process ownership acceptance. Test fixtures must track their genuine child and wait for bounded actual close before deleting roots; any discovered orphan/failure requires diagnosis, not relaxed teardown. Shared process-input and initial group-capture policies are not implicitly applied to this separate wrapper.
