# Narrow owner resolver draft, pending scope decisions

The adapter never receives a storageRoot argument from a plugin or persisted projection. An optional Core-created callback is bound to platform.storageRoot, orchestratorIssuerId, selected original wait registration and its configured wait root. It accepts only a strict fixed-key source reference: logical run ID; original event head/snapshot digest; full effects/signals byte digests; fixed source-root inode identity digest; selected wait effect key and wait ID. The projected payload separately binds original payload digest and manual intent receipt.

The callback derives canonical runRoot itself, rejects symlink/root changes, boundedly reads original source bytes, verifies exact references and pinned provider/wait-root configuration, invokes the original readRunEvidence contract, and returns the original selected effect's wait value. Original adapter validation still validates the value. It does not acquire a Run lock inside Wait ownership or issue capabilities/effects/network requests. The CLI constructs the same owner callback from its explicit validated scope and uses the same reconstruction function as actual consumers.

Still awaiting coordinator decisions: source-read budget must be explicitly owned (proposed conservative eligibility bound from original maxEntryBytes); whether immutable receipt bytes plus original Core effect authority suffice under Run→Wait, or whether requiring an additional held Delivery fence needs a narrow Foundation transaction API. No implementation of a second durable-store writer or arbitrary filesystem callback is permitted.
