# Remaining Kubernetes/Tailscale configuration authorities

Private source inventory after the V3 quality integration; no runtime, cluster or Tailnet claim. Classification does not authorize keeping configurable defaults in code. The three ProcessInput lifecycle values are centrally supplied, but do not exhaust either invoker's policy.

## Actual ownership chain

`docker/buster-runtime-entrypoint.sh` writes the runtime JSON's kubernetesFixture/tailscaleExposure sections. `production.ts` reads that file; `production-capability-sources.ts` requires a section when the corresponding capability is allowed. `production-cluster-options.ts` decodes the section into service options. `remote-prepared-execution.ts` calls `createBusterCapabilityRuntime`, supplying the separate central execution.processInput snapshot. The factory creates only enabled capability routes. KubernetesFixtureSettings and the Tailscale constructor capture their own options; actual command wrappers pass them to runProcessInput.

These sections are hand-decoded runtime-file authorities, not fields of the current central component schema. Plugin `schemas/config.schema.json` instead describes resolved provider invocation configuration. It does not own the invoker allowlists or budgets. Grants/routes must continue to gate capability use independently of migrating configuration.

## Protocol, request and derived semantics to preserve

DNS labels63, namespace prefix42 (identity-name construction reserves suffix space), ports1..65535, SHA256/immutable image syntax, Kubernetes object-kind and host/security restrictions are protocol/security constraints, not arbitrary operator defaults. String/path lengths (text1024, path4096, name253, digest71, metadata time64), secret-list count32 and storage exponent limit63 mix protocol validation with defensive budgets; maintain exact existing behavior and document deliberate ownership before changing them. Production string-array decoders also cap lists at32; constructors alone do not express the entire normal-path boundary.

Manifest omitted Service type means ClusterIP, omitted targetPort means servicePort, omitted StatefulSet replicas means1, and omitted annotations/security containers use empty structures for validation. These follow request/document interpretation; they are not a grant to invent operator fallbacks. Missing status phase/message and empty command stdout only affect polling/representation. Expiry fallback derives createdAt + requested retention. Service readiness shares the existing request readiness deadline after pod waiting. Wall-clock reads and injectable `now`/`execute` are clock/test seams; Kube's captured now has no effective read in the current implementation.

Provider-side config is separately authored: Kubernetes namespacePrefix defaults `test`, retention.mode defaults `delete`, retention.seconds defaults1800, readinessTimeoutSeconds defaults120 and secretReferences defaults[]; Tailscale readinessTimeoutSeconds defaults120, path defaults`/`, and retentionMode defaults `release`. Provider schemas constrain readiness1..3600 seconds, retention60..604800 and service ports. The provider sends `min(invocation.timeoutMs, readinessSeconds*1000)` and actual request identity/artifact digest. Those request defaults require their own explicit migration/historical snapshot contract, rather than moving into invoker policy or reinterpreting old resolved plans.

Environment process credentials remain separate: KUBECONFIG and Kubernetes service host/port flow into actual kubectl; Kube also passes HOME and a PATH derived from kubectl directory, Tail preserves PATH. Central policy must contain paths/references/installation identity, not embed secret values or expand what credentials allow.

## Smallest next coherent migration

Add explicit invoker sections to the central Buster component for current operator policy plus formerly code-authored command/poll/diagnostic/parser budgets. Decide installation-path and cluster-binding references once; preserve projected namespace and existing registry reference relationships instead of duplicating them as independent defaults. Route the captured settings through the production service/factory; reject retired runtime JSON/ENV authors including equal/empty values. Forward explicit service-account subjects through the normal decoder if they become supported settings. Keep request schemas/provider snapshots separate, with an explicit historical contract for their defaults.

Required tests: two actual invoker profiles through production decoding/factory; strict missing/invalid/legacy-before-command controls; both-chart exact delivery; actual low/high command output, timing, manifest/PVC/parser limits; constructor-vs-production identity/allowlist parity; immutable capture; original security and cleanup oracles unchanged. No live cluster operation is necessary for local command-lifecycle proofs, and such proofs must not be labeled live Kubernetes/Tailnet acceptance.
