# Historical authority and result reader: bounded implementation design

Status: source-only proposal using the existing maintained producer and immutable-original contract. No code integration, host stop, mount, capability change, guest extension or runtime test is authorized or performed by this document. Existing automatic-review restrictions on native-fixture expansion remain in force. This is not a second migration authority.

## Existing contract and blocking dependency

Reuse `scripts/buster-legacy-stop.py` and its policy/runtime/files/transaction modules, the immutable ext4 verifier, fixed sibling `legacy-migration/<transaction>/receipt.json`, original writer locks, `plan-jobs` and `runs` seals, and writable `plan-jobs-v2` / `runs-v2`. Preserve the existing capture/seal/resume phases, quota reservation before mutation, exact receipt publication, failure fence retention and completed-seal revalidation. Do not add a second CLI, snapshot route or caller-provided stopped boolean.

The maintained transaction currently stops k3s and then calls `verify_stopped_runtime`, which invokes bundled containerd's CRI socket. Prior analysis establishes that this endpoint can cease with k3s. A missing endpoint is not an empty inventory. The current captured-Pod set also cannot establish that no relevant writer was created between initial capture and stop. The fixed external browser cgroup must be included; Pod-only proof is insufficient.

The existing kernel-boundary proposal identifies a wider complete workload-root drain, but its impact on unrelated workloads has not been authorized. Its narrower admission-fence alternative lacks a proved activation/in-flight barrier. Neither alternative can silently become the supported producer. Therefore a working import-authorizing receipt producer remains blocked by a specific supported stop-proof design/acceptance boundary. Keep failures closed; do not make the consumer accept a root-owned but unproved declaration to bypass this dependency.

## Small implementation cut, after the stop-proof boundary is resolved

1. **Producer:** modify only the existing runtime stop-proof operation and corresponding transaction proof fields needed by the selected supported method. Retain transaction ownership, original locks, data/artifact preservation, symlink semantics, stable UUID/inode/digests, quotas and immutable receipt namespace. Capture explicit proof provenance sufficient for the verifier to reject receipts from an unsupported method/version. Do not treat a software hash alone as process quiescence. Actual runtime/kernel acceptance is required before enabling receipt issuance for that method.
2. **Receipt consumer:** one internal `preparation-historical-authority.ts` module reads only the fixed PVC sibling receipt. Require bounded regular single-link receipt bytes, trusted root-owned nonwritable ancestors, immutable receipt/transaction/migration directories and strict exact schema/digest validation. Bind transaction, configured volume/PVC identity, policy/capture identities, plan and runtime seals to fresh actual immutable-tree verifier observations. Compare enduring filesystem UUID, inode, inventory/store digests and byte/entry counts; historical boot/device/mount IDs are provenance, not equality requirements after a completed migration or across namespaces. Current traversal still enforces same-device/no-nested-mount rules. Reject observation-only objects. Mint the private `VerifiedHistoricalSource` value solely after those checks, using an internal concrete implementation/private token rather than a cast or exported test constructor.
3. **Import activation/publication:** replace `runHistoricalImport`'s refusal only with this actual verifier followed by the already maintained owned materialization/channel/batch checks. Bind publication to the exact source descriptor and sealed result/runtime inventories, preserve originals, and persist publication association before service activation. An incomplete, conflicting or unverified candidate must never be treated as current metadata. Keep one fixed path/transaction topology, not arbitrary request-selected roots.
4. **Historical result/evidence reader:** add one read-only consumer of that verified authority. Keep the current v2 blob-store path unchanged. A persisted historical `resultOrigin` selects the verified original result/runtime roots and exact original record association; there is no fallback to whichever path happens to exist. Validate requested job/result digest, bounded size, result schema and identity against the retained terminal record; open regular non-symlink/non-FIFO files under the verified immutable ancestry, bound reads before allocation and verify bytes/digest. Evidence must retain existing file-type/path/size/hash checks, including FIFO refusal. Return the exact original bytes and URLs/identities; never rewrite resultOrigin to v2 merely to reuse a reader. Connect this reader explicitly to the store/service's historical result and evidence branches.

Keep configurable byte/count/time policies with their existing Buster/preparation owner and pass them explicitly. Protocol schema versions and proof fields are not an excuse to add operational fallback defaults. The receipt's filesystem protection, actual source seal and supported producer proof are all needed; a digest authenticates consistency but is not a secret signature or standalone authority.

## Tests required before enabling the path

Reuse existing producer unit tests, real historical-record producer, `materializeHistoricalImport` UID1003 filesystem fixture, immutable verifier and original compaction regression. Do not replace the original compactor, records, results, locks or HTTP route with mocks.

- Unit/rejection tests may prove strict decoder, digest/identity mismatch, bound enforcement and no-publication behavior. Clearly mark any modeled syscall/owner boundary; those tests cannot produce accepted live authority.
- Actual supported producer tests must establish the chosen capture-to-stop race closure, external browser subtree, inherited/open-FD and mmap writers, restart fence, original locks, immutable old-entrypoint restart refusal, partial failure/resume and bounded retention. No quiet-time or absent-socket positive. These require separately reviewed permissible infrastructure; this document does not broaden host or guest authorization.
- Consumer tests require genuine filesystem protections and fresh verifier observations, wrong receipt/transaction/volume/store/runtime identities, missing/changed flags, incomplete publication and namespace/boot provenance behavior. A fabricated branded object is not a positive control.
- Reader tests require real historical result/evidence files, exact bytes and identity, missing/truncated/corrupt data, symlinks/FIFOs, limits and a positive current HTTP terminal replay after legitimate publication. Assert no archive reconstruction or execution on terminal replay; verify current v2 results remain unchanged.
- Keep every original compaction quota/CAS/crash/CLI/HTTP/artifact assertion and deadline through the mapping in [the regression migration proposal](buster-compaction-fixture-migration-20260921.md). Full acceptance remains blocked until both authorized publication and historical result reading actually work.

## Ownership and activation

The existing stop producer owns receipt generation; the new internal verifier owns conversion into authority; the existing preparation parent owns publication; the explicit reader owns retained-byte access. No generic permission framework, alias rollback, new producer or exception path is needed. Integrate incrementally only with fail-closed activation: validating structures or reading untrusted observations must not open the service. The unresolved stop method is a hard prerequisite, not work that a test helper can complete.
