## Required original scopes, retained unabridged

- `npm test --prefix skills/buster/plugins/security-providers`: both complete live-function and database-freshness files. Direct constructor callers gain explicit new policy using authored component values; their old assertions and native tool behavior remain. No replacement of native scan by a result fixture.
- Full `verify:test-gate:security-implementation`, `verify:test-gate:security-parity` and `verify:test-gate:security-cutover` chain: existing remote vertical, controller Go tests, provider registry, plugin types, docs schema/error/example/controlled-language checks and Nova scaffold regression. The original remote vertical directly constructs Buster service, so it cannot replace SS2's production runtime loader proof.
- Full `tests/verification/deployment/registry-trivy-native.test.mts` with actual pinned executable, genuine DB artifacts and actual authenticated TLS OCI responses. Registry client/deployment original suites and full remote-runtime config also remain required after removing duplicate scanner descriptor.
- Complete component generation/bundle/packaging/both-chart suites, actual entrypoint before-effects gate, relevant worker-local/readiness consumers, scanner provider/schema types and canonical affected lint. No whole repository success is inferred from these affected scopes.
- Existing signed live security preflight stays a separate unexecuted live obligation. Local models cannot close native worker/controller/remote cluster behavior.

Current original provider tests locate tools/cache through test-only environment bindings and fallback candidate paths. These are test fixture locators, not permission for new production defaults. In coordinated runs bind the actual executable/cache identities and tool guard explicitly. If no valid real DB is available, native tests remain failed/blocked—not skipped or supplied fake DBs. The existing installer/version lock is artifact provenance; its presence is not proof those actual bytes exist or remain fresh.

## Mutation/control proposal

Freeze actual source hooks and expected failure causes before execution. All controls require passing baseline, confirmed application to bound bytes, unchanged full relevant suite and zero unexpected source drift.

1. Restore 900000ms execution cap, 67108864-byte output cap or original PATH independently: respective low/custom profile must fail its real effect oracle; other test-specific request limits remain unchanged.
2. Reintroduce DEFAULT_TRIVY_DATABASE_POLICY/optional fallback: missing direct/bundle settings must no longer silently pass. Required-input negatives reach admission before filesystem effects, not a later missing tool failure.
3. Restore each fixed database age, database bytes and metadata16384 quota independently: actual prepared boundary file/timestamp profile must detect the wrong acceptance/refusal.
4. Restore title2048/message4096/resolution4096, including both title consumers: exact projected text profiles fail. Never substitute missing fields or malformed JSON as the intended signal.
5. Restore abort-before-output-cause ordering: a genuine combined output overflow must fail if TIMEOUT replaces OUTPUT_LIMIT.
6. Suppress source-to-service forwarding, use a stale component generation, retain caller nested registryAccess alias or restore duplicate registry input author: full service/capture/real TLS oracles detect effect differences and unauthorized credential delivery. Choose exact independently reviewed controls once the shared registry model is accepted.

These controls do not prove production cleanup/resource ownership. Child/credential cleanup, unbounded manifest allocation and parsed output memory remain explicit overall-goal requirements and require their own eventual genuine proofs.
