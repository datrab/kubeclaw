### ICD-001 — const-only operators do not close requested configurability (blocking C0-C/E)

`core-policy-domains.md`, `core-policy-domain-closure.json` and all twelve numeric
operator rows propose **only** the existing numeric literal as a required schema
`const`, while declaring their domains closed and broader tuning a separate future
proposal. This can make a coherent **value-preserving first migration** and avoids
inventing unsupported ranges. It does not meet D20's source-change-free meaningful
component tuning or D17/F4/F-EFFECT for the adjustable policies already classified
as operators. Requiring the literal in a sole author removes a fallback author;
it does not create a second valid behavior profile.

The source gives concrete counterexamples to treating all twelve as intrinsically
immutable: JSON workload caps, log count, diagnostic clipping and drain cadence
are budget/cadence choices, not digest/kernel/wire identity constants. Lock
stripe width is legitimately recovery-sensitive; arbitrary 1..64 widening would
also be unjustified. Neither concern licenses the author to narrow the whole
agreed requirement set. A1 requires a user decision for changed target scope.

Correction: retain current constants as current-state facts and a bounded
migration option, but leave tunability/domain closure open until each policy has
a supported, justified adjustable domain and real A/B case, or a concrete
independently checked invariant/nonadjustable reason consistent with the task.
Where meaningful tuning is intentionally excluded, record an explicit scope
decision; do not infer approval from preservation or unknown deployment capacity.
No invented Buffer/safe-integer/stack/timer-wide domain is requested here.
