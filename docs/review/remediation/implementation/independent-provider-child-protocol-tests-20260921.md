Status: static test review only. No production or test edits, child launch, sandbox operation or runtime acceptance. [Bound sources](../../evidence/independent-provider-child-protocol-tests-20260921/source-identities.json) include the private test, its coverage declaration, the session-class draft and prior independent source review.

The four actual-child cases have useful positive oracles: two RPCs must be emitted while execute is waiting, reverse-order replies must retain input ordering, detached `invoke` exercises method binding, provider `this.values` must survive into cleanup, import-time console output must be protocol-framed, and an unawaited RPC must produce the exact error followed by exit 1. Closing the actual child with code 0 after cleanup is stronger than a mocked transport result. The helper launches the live child path: execution only proves the private class after that exact draft has been integrated and bound.

Two oracle gaps should be corrected before calling the advertised abort/late-reply coverage complete:

1. In the early-success variant, the test waits for the second RPC's abort but never rejects an additional abort for the already-resolved first RPC. For example, removing `request.detach()` leaves the fulfilled Promise unchanged while emitting an erroneous capability-abort on later session abort; the current predicates can still pass. After an ordered cleanup/close boundary, assert the exact capability-abort ID multiset and reject leftover unexpected messages. Do not replace this with an arbitrary delay.
2. The late reply is sent after the expected result, followed by cleanup. Checking cleanup-result and exit 0 proves that this sequence does not terminate with error, but does not prove that the late reply is ignored: additional result/abort/log messages can remain unexamined in the queue. Keep a complete transcript or expose the remaining queue and assert its expected contents after close. A deliberately introduced unsolicited response should then fail a concrete assertion.

The helper's normal cleanup kills a still-live child and awaits actual close before removing its directory. Error paths are less robust: cleanup is registered only after temporary creation/write/spawn setup, and a rejected `closed` promise skips `lines.close()` and directory removal. Register ownership cleanup early and use `finally` for temporary removal; retain the original spawn/protocol failure. JSON parse exceptions in the stream callback and outstanding waits after child closure are not converted into immediate contextual waiter failures, so failures can surface as uncaught exceptions or the five-second timeout. These are test-harness robustness issues, not an observed production defect.

The tests do not exercise a caller-provided AbortSignal, already-aborted invocation, unsuccessful capability reply, duplicate successful reply, repeated actual SIGTERM, loading/factory failure, cleanup rejection, binary logging or resource-message values. This is acceptable only as explicitly limited new coverage: retain the complete original Runner/real-provider contracts and map which existing cases cover these boundaries; any original requirement still lacking a real case remains open. In particular, IPC abort cases are not repeated-SIGTERM evidence. The prior child-source review's cooperative cancellation, forced-stop, evidence/cleanup ordering, output/log limits and actual process cessation obligations remain mandatory.

Keep the original handler-removal control against the final integrated child and both full original contract scripts, plus actual-path canonical lint. These direct Node protocol cases do not establish the sandbox, native preparation, image packaging or broader Buster completion.
