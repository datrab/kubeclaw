# Independent provider child lint-boundary decision

Decision: the proposed two exact-file declarations are architecturally justified infrastructure boundaries, rather than a disguised substitute for the session-state refactor. This is a static policy decision, **not** integrated lint, runtime, sandbox or full quality acceptance.

[Independent byte comparison](../../evidence/independent-provider-child-boundary-policy-20260921/source-check.json) confirms that removing the two identical explanatory-comment/path additions reconstructs the entire original lint policy exactly. The live policy still equals the before snapshot. No wildcard, ignore, rule implementation, threshold, environment access exception or mutable-state exemption is added.

The dynamic-module rule explicitly permits declared loaders. The inspected Buster child imports the provider selected by its parent's registration/module path; importing that module is its actual loader responsibility. It is not a new arbitrary configuration loader. The same policy already names the common isolation child, which imports its commanded provider module. The Buster console assignments likewise implement protocol routing: provider console output is encoded into IPC log messages instead of corrupting the JSON command/result stream. They are not ordinary application debug statements. The common isolation child also intercepts console methods, albeit to stderr.

An exact-file exception still allows all uses of those two APIs inside that file, including future inappropriate ones. The accepted rationale therefore remains tied to the small process-entrypoint/loader responsibility; it is not authorization to move unrelated code there or to interpret a successful lint result as validation of imported modules. Parent registration/pinning, filesystem permissions, protocol validity and native process containment are separate contracts.

This changes which infrastructure file the existing policy recognizes. It must be documented as resolving the classification of seven findings, not as seven code defects eliminated by refactoring. The five module-state findings must still be fixed by the actual session owner. All other discipline rules remain applicable.

Before closure, integrate and bind the exact policy plus child; run canonical lint on the actual child and show the other rules remain enabled. A narrow policy-control check should verify that a neighboring ordinary production file still rejects dynamic import/console and that mutable state in the exact child remains diagnosed. Preserve complete original Runner and real-provider cases, the corrected direct child protocol tests and the meaningful handler-removal control. Maintain the execution-boundary documentation and its native/image limitations. None of these execution requirements has been performed in this review.
