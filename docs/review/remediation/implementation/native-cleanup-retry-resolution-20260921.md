# Native source-cleanup retry resolution

The bounded Core retry resolution is independently accepted; this does not close Buster preparation, native cutover or IFR16. Root assigned this separate dependency after the two-phase integration exposed a same-journal recovery gap: a failed source-cleanup row is immutable and currently causes recovery to reject even after a separately owned successful retry resolves the original effect.

## Acceptance criteria recorded before Core edits

1. Keep original and predecessor failed result/receipt bytes unchanged. Never launch cleanup of a cleanup through the new hook.
2. Process ordinary original attempts before resolving deferred failed-cleanup rows, regardless of journal insertion order. The deferred list is bounded by the existing journal record ceiling; no new unbounded store or journal scan inside a callback.
3. An optional lookup-only callback returns an original envelope and an already-successful distinct cleanup envelope, or null. It cannot assert success with a Boolean. Core reads the original result from the original journal and verifies both cleanup operations against that exact failed original result and the same effects digest, fixed cleanup profile and full claim/envelope identity.
4. Original, failed predecessor and successful retry must have positively quiescent ownership. The successful retry must pass the existing archived stdout, final counters, result binding and executor-finalizer verification. Unknown, missing, live, failed or unarchived evidence leaves admission fenced.
5. Preserve all original cleanup recovery tests. Add actual filesystem/journal tests for both insertion orders and repeated recovery, immutable bytes, missing associations, foreign effects/predecessor/original and invalid retry evidence. Ownership in these tests is explicitly modeled; no kernel proof is implied. A private semantic mutation must be detected.
6. Run canonical scoped lint and Core type checks, record complete commands and terminal outputs, and obtain fresh nonauthor review.
7. Update recovery documentation and Buster integration status with the exact lookup authority, retained uncertainty and evidence limits. Do not claim productive Buster retry completion from this Core seam alone.

## Implemented boundary and author evidence

Core now defers failed `kubeclaw.native-source-cleanup@1` rows during its existing journal iteration. After ordinary original recovery finishes, optional `resolveFailedCleanup` returns a detached pair of original/successful-cleanup envelopes. Fixed journal/profile values are captured before calling it. Core rereads the original accepted sealed result, validates both cleanup operations against the complete original reference and the same effect digest, requires distinct attempts/claims and positive quiescence, and reuses the archived-result verifier. A missing hook or null association leaves admission fenced. Original failed receipts remain unchanged. No additional journal scan or persistence format was added.

Author validation: all original 24 cleanup cases and 13 new same-journal cases pass (37/37, no skips) under actual GNU flock. Both insertion orders and a second recovery invocation are covered. Ownership is explicitly modeled; journal admission, locks, output spools, result finalization and persisted receipts are real. Core typecheck and scoped canonical ESLint pass. Removing only the equality check between predecessor/retry effect digests in a private copy is detected by the strengthened different-effect case with matching successor ownership identity and valid archived success.

Raw evidence is in `docs/review/evidence/native-cleanup-retry-resolution-20260921/`. `tests-final.txt` is the final complete run. `tests-run1.txt` preserves a missing cached libtalloc setup failure; `tests-run2.txt` preserves the new repeat-recovery fixture's attempted second spool creation. The fixture now reuses its existing sealed result; no production assertion was weakened. `tests-run3.txt` passed before the wrong-effect case was strengthened to update its modeled owner. The first private-mutant invocation was blocked by Node's prohibition on stripping TypeScript under node_modules; its output is retained separately, and the executed mutant uses an isolated temporary source tree.

Commands use `/usr/local/bin/node --test --test-concurrency=1` on `worker-native-cleanup.test.mts` and `worker-native-cleanup-retry.test.mts`, through cached proot binding the actual GNU flock binary at `/usr/bin/flock`; cached `usr/lib` is supplied in `LD_LIBRARY_PATH`. Lint uses `charts/kubeclaw/files/config/eslint.config.mjs` on both changed Core modules and the new test. `run-mutant.py` preserves the exact mutation, import redirection, command and outcome.
