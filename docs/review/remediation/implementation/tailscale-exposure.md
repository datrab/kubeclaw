# Tailscale exposure ownership and default HTTP ports

Implemented 2026-09-09 for PCR-TAILSCALE-001/002. Independent counterreview passed after both transition blockers were fixed; historical findings are unchanged.

The provider now treats an empty WHATWG HTTP URL port as the effective port 80. Explicit `:80`, implicit 80 and non-default 8080 retain the same strict service/namespace DNS checks. The capability still verifies that effective port against the actual lease service contract.

Exposure ownership is a canonical SHA-256 identity of the immutable attempt resource and target lease/namespace. A separate durable annotation binds the service, port, expiry, path and requested hostname. Same-attempt replay adopts matching existing work without issuing another patch; changed payload for the same owner is rejected. A new attempt obtains a different owner. Prepare and release patches use the Kubernetes resourceVersion precondition, and old cleanup detects supersession without changing the lease. The human-facing release command also tests the owner atomically before disabling exposure.

The controller's exposure status now acknowledges the owner and observed lease metadata generation. Ready/Off is accepted only when both match current metadata; the previous generation's Ready URL cannot satisfy a new request. Controller URL selection also rejects an old ingress hostname when the requested hostname changed. The client checks the exact desired exposure specification and path as well as the allowed HTTPS suffix.

Ingress mutations use the actual object version: updates are conditional, deletion requires the observed UID and resourceVersion, and the controller rechecks the current lease owner/generation before mutation. A late old reconcile cannot overwrite or remove an already replaced ingress. Its old status acknowledgment also cannot satisfy a newer client. Service/Endpoints are only inspected, never removed by this path.

Independent review exposed two additional transition defects, now corrected. Status-change detection includes owner and generation, so same-spec takeovers persist their new acknowledgment through the original ready-lease reconciliation short circuit. Prepare's conditional patch also records a bounded predecessor-owner chain from the current durable lease; unfinished takeovers inherit the chain. Only a matching observed Ready/Off generation permits discarding older entries. A canceled takeover can therefore retire its explicitly transferred predecessor instead of leaking it. Controller adoption and Off cleanup require the ingress's exact lease UID labels and namespace, current or recorded predecessor owner, current lease acknowledgment identity, and the original object preconditions. Unknown owners, foreign lease UIDs and corrupt lineage fail closed. The chain is limited to 64 owners; exhaustion rejects a new takeover without mutation.

## Verification

- Original controller suite plus new Go HTTP protocol tests pass under `go test -race`. The new tests exercise actual controller exposure creation/update/deletion, owner/generation Ready and Off acknowledgments, old-hostname rejection, and lease/replacement races causing refusal or 409 rather than mutation.
- New native kubectl tests use the installed executable and original capability/process runtime against an explicit local HTTP Kubernetes wire fixture. They cover the PATCH-before-controller-status prefix, same-attempt replay, altered prepare/release inputs, later-attempt takeover, delayed old cleanup, conflicting release resourceVersion, and final matching Off acknowledgment. The fixture is not represented as a Kubernetes API-server or Tailscale operator implementation.
- Review regressions exercise actual `reconcileReadyLease`: owner-only and generation-only changes persist, while unchanged status still short-circuits. Parallel native kubectl A→B→C pending takeover and cancellation retains the exact predecessor chain; actual controller Off reconciliation removes the authorized predecessor and rejects unknown owners, foreign lease UIDs and malformed lineage. Existing replacement races still reject stale writes/deletes.
- Provider tests pass for implicit/explicit port 80, 8080, unauthorized host and mismatched service/namespace. Provider TypeScript build and plugin-runtime TypeScript check pass.
- Original Tailscale implementation/parity/cutover checks pass. Their hard-coded `/usr/local/bin/kubectl` prerequisite was replaced with the existing executable resolver, using the actual installed kubectl. Those historical suites contain injected command responses; their `mocks:0` output is not treated as live evidence.
- New helper/test canonical ESLint checks pass. Existing runtime direct-environment-access findings and provider complexity findings remain visible, without suppressions or changes to lint policy. The changed runtime's prepare method was separated from public-URL validation to keep its new logic within the existing complexity limit.

## Deployment and lifecycle limits

CRD status schema, controller and capability must be upgraded together. An older controller without owner/generation acknowledgment cannot produce a successful new exposure result. No cluster, tailnet or operator was mutated; no CI or deployment ran. Local HTTP/Helm evidence does not prove live ingress reconciliation or operator delivery. The ingress URL is control-plane evidence; actual content/network verification remains a separate configured check.

The original lease expiry remains unchanged throughout exposure and cleanup; no new short TTL or expiry reset is introduced. This bounded repair does not establish the seven-day final-demo lifecycle or its operator handoff. The existing caller must not invoke normal exposure cleanup while that transferred demo is still required. Namespace expiration/deletion remains owned by the deployment lease. This slice does not claim final-demo D06 completion.
