# Registry client contract: IFR-08-001/002 and IFR-09-001

The previous pod-local anonymous origin never established shared BuildKit, Node manifest, scanner or node CRI trust/authentication. The mirror manifest alone did not route clients. The new registry-clients.v1 helper is consumed by the real Buster entrypoint, with explicit operator origin/transport, scoped credential environment references and optional supplied CA. The chart requires exactly one named Buster runtime, mounts only its registry credentials/trust, and rejects conflicting old overrides. The image packages the relocatable original generator. No endpoint, credential or CA is invented. Own root/client/auth fields are closed; malformed or misspelled mirror configuration fails rather than silently disabling routing.

BuildKit and node configuration route Docker Hub only through the separately configured mirror. Generated node configuration is mode 0600 and refuses overwrite. Generation does not install host settings or establish CRI reachability. The Node manifest verifier uses the mounted CA; the native scanner uses an exact-host temporary Docker auth configuration and --cacert, preserving sanitized environment and database freshness. No global scanner credential variables or insecure HTTPS bypass are introduced. Explicit HTTP lab image scanning rejects with SECURITY_SCAN_HTTP_LAB_UNSUPPORTED before launch; this is a documented incomplete lab pipeline, not hidden HTTPS relaxation.

Registry lifetime changes are documentation only. Namespace deletion never implied shared-image deletion. No PVC size/class, capacity budget, GC, log expiry or automatic deletion is added. Required image references, active demos/leases, waiting runs and retained acceptance evidence still need an operator-owned lifecycle design. Existing mirror PVC is unchanged.
