# Request-owned Prism worker cancellation

This corrects an executable remainder of PCR-PRISM-WORKER-003. The HTTP handler already created a request cancellation controller, but only nonce authentication observed it. `executeWorkerAttempt` did not pass it to the shared Worker Core. A caller disconnect therefore left actual artifact HTTP I/O active until a separate attempt/phase deadline.

The original service at local 6f300ec was exercised with the real HTTP server, shared WorkerAttemptExecutor, PrismEngine, WorkerArtifactClient and content-addressed store. A deliberately stalled actual artifact response exposes the boundary; no engine, provider, executor, fetch or store replacement is used. The read and full-log upload both remained active after a real caller socket destruction (two failures); the normal bound result and durable full log succeeded. The same three tests pass after forwarding the request signal into Core and avoiding cancellation after a normal response end.

The synchronous request owns one attempt. Control persists a result only after receiving the worker response, and the worker has no separate durable lost-response result queue; disconnect cancellation is therefore scoped to that admitted invocation. The engine retains its existing ownership checks and shared Worker Core keeps termination/drain authority. Already persisted upload bytes remain and are checked, not claimed rolled back. The actual trusted-loopback SPIFFE header path is used for local HTTP admission; this does not prove deployed Envoy/SPIRE identity.
