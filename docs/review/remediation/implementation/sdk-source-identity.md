# SDK001: coupled source and run identity cutover

This slice extends the artifact and effect cutovers. It does not close the entire canonical-consumer inventory.

## Contract boundary

The actual Project compiler now writes `identityEncoding: kubeclaw-json.utf16.v1` into ReviewSource and every SourceBinding. Capture hashes the input and unsigned ReviewSubject with the corresponding strict portable JSON codec. The subject carries the tag inside its signed body. SourcePreflight requires exact binding/subject codec agreement before recomputing the contract digest. All five closed input positions in four plugin schemas accept exactly this optional version. Unknown or explicitly undefined tags are rejected by the SDK parsers; tag removal cannot reinterpret a signed portable subject.

Absent tags retain the exact existing locale-sensitive algorithm. Existing stored authority is neither inferred to be portable nor silently upgraded. An unverifiable old contract blocks admission. Actual preflight, architecture report, human approval, and Blueprint summary producers select portable artifact encoding only for explicitly tagged subjects. Implementation completion already uses the portable artifact contract from the preceding slice. Original artifact-byte/ref verification and Git source checks remain in the real consumers.

The first real Unicode-policy en→sv paused-run regression failed before reaching the subject reader: the run snapshot itself hashed the same policy using the old algorithm. The retained pre-fix log records `RUN_SNAPSHOT_INTEGRITY_INVALID`. Consequently the slice also versions the actual snapshot boundary:

- New `execution-graph-snapshot.v3` uses portable JSON and code-unit ordering of its node/edge representation. Runtime scheduling order is unchanged. Version v2 retains the exact historical serializer and ordering.
- New `run-snapshot.v2` hashes the complete envelope with portable JSON. Version v1 retains its historical serializer. Unknown outer or graph versions fail closed.
- `verifyPinnedGraph` reconstructs the incoming graph using the stored graph version. `executePrepared` verifies it before adapters start and passes that verified version to PipelineRunner, including ordinary recovery, signaled resume, and administrative continuation. The original digest remains the journal/run identity on old runs. Stored registry graph references and snapshot bytes are never rewritten.
- `readRunEvidence` already invokes the central snapshot assertion, so projection accepts the explicit new envelope and rejects unknown versions. Administrative cancellation uses the graph returned by the same verifier.

## Actual Project CLI recovery

Independent review reproduced a further real boundary: the original Project CLI recompiles `project.json` on `--recover`/`--signal`. Applying the new default to an old run produced tagged Source inputs and therefore `RECOVERY_GRAPH_DIGEST_MISMATCH`, even when the graph serializer correctly selected its historical version.

`compileProjectRecovery` now reads the integrity-checked snapshot, parses the original Source codec, recompiles the supplied project with that explicit compiler mode, and verifies the entire compiled graph before runtime admission. It does not substitute saved nodes for user project data; changed tasks and other inputs still fail the original graph check. Both recovery commands use this path. The helper imports explicit `@kubeclaw/nova-core/run-snapshots` and `/run-root` exports, preserving the separate nova-project/nova-core package layout in bundles.

The independent original 13-stage CLI probe compares an unchanged historical CLI plus the new compiler against the fixed real `pipeline.ts --recover`, using the same actual historical run. The first produces graph mismatch; the fixed CLI reaches the run's original `RECOVERY_RUN_TERMINAL` guard. This particular run was already blocked and was not reopened. Its journal and snapshot bytes remain identical. Successful complete historical resume is separately demonstrated by the Core approval-graph probe above; the terminal CLI probe does not claim that result.
