# Telemetry store field policy and bounded projection

Addresses PCR-TSTORE-001 and PCR-TSTORE-002 under decision D01.

## Actual producer and consumer

The built-in telemetry observer creates `telemetry-envelope.v2`, applies the SDK's existing redaction to event identity/payload, and invokes `telemetry.emit`/`append`. The selected telemetry-store adapter writes the `telemetry/plugin-events` stream through the existing `FileDurableRecordStore`. Other authorized callers can reach this adapter boundary without that observer's field redaction.

The adapter receives no trusted field-level credential provenance or authority proving that a credential was generated by the pipeline for a demo. Therefore this change introduces no unredacted-demo exception based on field names, a generic `key`, a namespace, or a payload's self-asserted provenance. Protected fields remain protected when provenance is absent. This is not a claim that the full D01 provenance feature now exists.

## Implementation

A bounded snapshot validates the complete incoming JSON graph before redaction. It rejects cycles, excessive depth, excessive visited nodes, getters/setters, proxies, unsupported prototypes/types, sparse/extended arrays, nonfinite numbers, invalid Unicode, and excessive JSON bytes. Limits are depth 64, 100,000 visited values, and the configured `maxRecordBytes` input byte budget. Shared acyclic references remain valid; each expanded occurrence counts. The snapshot reads own data descriptors without invoking accessors. Even a subtree about to be redacted must pass validation first.

The validated snapshot is projected using the existing redaction marker. Protected fields include the prior authorization/cookie/password/secret/token families plus API-key/credential aliases, private/access keys, connection strings, and explicitly named personal data such as email, phone and userData. This is field classification, not a blanket string censor: harmless correlation fields and concrete diagnostic messages remain intact. Arbitrary free text cannot be proven free of secrets or personal data by this field policy; producers still own safe source content.

Oversize input fails explicitly before persistence, and the durable store continues to validate final projected size. There is no truncation path, silent omission, partial append, new central store, or logging disable. Existing producer/artifact owners retain canonical source diagnostics; Clawdeck remains the durable collection owner under D01. The sink preserves source artifact references and explicit display-truncation metadata, never edits the referenced source file, and cannot restore information already shortened/redacted upstream by the SDK observer.
