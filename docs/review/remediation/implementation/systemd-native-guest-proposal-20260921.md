# Genuine systemd parser and original native gate: disposable guest proposal

Preparation only; the coordinator owns launch after fresh artifact review. Use
a new cache/disk and independent private source export, preserving every earlier
failed and successful VM artifact. This is not a deployment or host service action.

The guest executes the complete unchanged `native-worker-node.test.mjs` module
(five cases) as actual UID 0 with the authenticated systemd 257.13 runtime, and
both original native live modules (12 cases) on the same frozen current Core
source. There are no test-name filters, skipped cases or changed test deadlines.
A missing prerequisite or either gate failure produces a nonzero final status.
The previous combined guest failures remain historical failures.

Create an independent export from current complete skills, contracts, scripts,
tests, charts, infrastructure/configuration and installed dependency roots, plus
package metadata and versions. Exclude only private caches and Git metadata. Record exact entry types/hashes/symlinks and compare original test
identities. Existing dependency bytes are copied independently and bound in the
full snapshot. The guest uses a readonly 9p export. The reviewed host wrapper
checks the entire entry set, containment and every byte before and after QEMU;
it also binds the disk, initrd and tool/kernel artifacts. This replaces the
redundant, expensive guest walk of approximately 39,000 files that exhausted the
previous diagnostic. The guest checks a focused critical-file manifest before
execution; it does not weaken host full-source verification.

Install no host packages. Copy the authenticated extracted Debian parser runtime
into the new guest disk under `/opt/systemd-parser`, preserve genuine unit
files, and provide a private PATH forwarder that only execs its real glibc loader
and analyzer with unchanged arguments/status. Guest-only readonly bind mounts
expose genuine systemd unit defaults; no stub targets, fake parser or proot
fake-root is used. The original ExecStart `/usr/bin/env` remains real. The
parser version is reported before tests. All guest disk ownership changes stay
inside this disposable guest.

Keep the established envelope: 1 GiB guest RAM, two TCG CPUs, 64-MiB TCG cache,
no network or KVM/passthrough, 8-GiB private disk, 120-second boot and 900-second
outer wall bounds, existing CPU/address-space/log/shared-memory guards. The
native delegated test pool remains 512 MiB, 4,096 tasks and its original CPU
quota. No memory refusal or timeout is bypassed. Previous signed Alpine kernel,
toolchain and GNU flock packages are reused by exact artifact identity.

Acceptance requires full source/runtime manifests, author verify-only with no
boot, fresh independent preparation review, then exact console/results from the
coordinator's run. Parser and kernel outcomes are separate; complete 17-case
execution does not prove systemd PID1 activation, production K3s/containerd,
live-node reservations or the complete Buster rollout. No actual image build is
claimed.

## Materialized checkpoint

The new snapshot contains 33,975 entries and 30,463 independently copied regular
files. The complete current source roots were copied once rather than mixing
current package metadata with historical dependencies. The three original test
module identities were compared with current source. The parser disk copy matches
the frozen authenticated runtime manifest. Guest init, forwarder and focused
identity checker are retained as reviewable inputs; no test source was modified.

Materialization completed, but two verification-only attempts refused the
unchanged 512-MiB initial anonymous-plus-kernel memory guard before boot. Both
refusals remain represented by the retained refusal log and current verification
log. Cache-release hints affected only the newly owned regular files; a subsequent
10-second quiescence did not satisfy the guard. No global cache drop or increased
allowance is authorized. The fixture therefore awaits a successful unchanged
verification-only run and fresh review before coordinator launch.

## Preparation binding corrections

Coordinator review found a stale command-name snapshot, artifact verification
limited to five files, and missing source modes/tool-library identities. These
initial artifacts are preserved under `superseded-binding`. The corrected wrapper
verifies every manifest artifact before execution and every immutable artifact
afterward, including its own code and guest driver. Only the intentionally
mutable guest disk is excluded from equality after execution; its final hash is
still recorded. The concrete command was regenerated from the actual wrapper.

Source modes, including the root and every directory/file/link, were captured
from the already frozen export without copying current in-progress source again.
Full entry-set/type/link/byte/mode verification remains mandatory before and after.
A separate manifest binds the complete actual QEMU tool tree, its resolved root,
firmware, modes and symlink targets. Existing external absolute-link referents
and the host ELF interpreter are explicitly recorded. The shared baseline tree
was not modified. Tool-runtime equality is checked before and after execution.
These stricter checks preserve all resource guards and do not authorize a boot.
