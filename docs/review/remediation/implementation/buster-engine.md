# Buster engine remediation

Scope: PCR-BUSTER-ENGINE-002/003/004 and PCR-KUBERNETES-FIXTURE-002. PCR-BUSTER-ENGINE-001 remains unresolved for hard aggregate CPU, memory, and process accounting across provider, parent-side capabilities, and report adapters. Forwarding cancellation is a prerequisite, not that accounting guarantee.

## Current changes

`process-input.ts` attaches error handlers to stdin, stdout, stderr, and the child before sending input. Report-adapter, Kubernetes fixture, and Tailscale fixture subprocesses share it. A stdin failure is a rejected operation with its original cause, rather than an unhandled host event. Timeout, cancellation, output overflow, and native leader exit start one owned cleanup: TERM allows a supervisor to reap descendants, followed by KILL after 250 ms if needed. Settlement requires both native close and namespace-aware Linux process-group nonrunning acknowledgement within one 1,500 ms disposal bound. The audited Linux identity/scan primitive is shared with command-runner through foundation/processes, with a declared foundation dependency and no compatibility wrapper. Incomplete disposal destroys host pipe ends and rejects typed ProcessInputCleanupError, preserving the first failure as cause. Report adapter snapshots survive that disposition. Captured output remains bounded. This is process-group acknowledgement, not cgroup containment or prevention of arbitrary setsid escapes; an escaped pipe holder produces bounded explicit failure.

`provider-capabilities.ts` owns pending parent invocations, rejects duplicate IDs and more than 32 outstanding requests, forwards a combined invocation/context/session abort signal, suppresses replies after cancellation, and allows bounded draining. The SDK's optional third invoke argument carries that signal to actual Buster capability routing. Both parent and child reject a provider result with unresolved capability calls. Per-call child cancellation travels over the existing protocol. Parent asynchronous line handling has a terminal rejection handler; it no longer lets a rejected late callback become an unhandled host promise rejection. Context abort preserves the original error and terminates the session. Termination rejects explicitly if close has not arrived within its bound. A capability implementation that ignores cancellation produces a drain timeout; this mechanism cannot forcibly stop arbitrary parent-side JavaScript or guarantee it stops mutating after timeout.

Provider snapshots are removed after confirmed termination and draining; failed disposal keeps the snapshot. D07 overrides the original suggestion to retain compact receipts only: terminal workspace cleanup removes the temporary archive, extracted source tree, and provider snapshots. It preserves durable job/source records, results, artifacts, evidence, observability, and scratch/log files. Retained-fixture cleanup removes its temporary repository, not the entire attempt directory. Workspace input removal requires a completed run with no cleanup errors and every attempt in completed execution state. Retained fixture repositories require successful fixture cleanup and termination. Extraction failure removes partial inputs before any provider starts. Cancelled, failed, interrupted, or uncertain work stays intact. Restart recovery does not delete inputs: no persisted child ownership/reconciliation currently proves that orphan providers or parent capabilities stopped. ENGINE-004 therefore remains partial; orphan/restart cleanup is blocked until that proof exists.
