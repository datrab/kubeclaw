## Behavior changes

### DELETE_LEGACY
- Deleted silent substep `FORGE.md` skipping in `readForgeInstructions()`.
  - If `moduleConfig.substeps` is configured, every substep id must be a non-empty string and every `<substep>/FORGE.md` must exist and be readable.
  - This resolves `P3-055`: configured substep instruction artifacts are required, not best-effort.
- Deleted the disabled Qdrant/memory recall block from the Forge prompt builder.
  - Removed the commented-out recall implementation, runtime `memoryBlock`, runtime `recalledMemoryIds`, priority-header memory references, and prompt assembly memory section.
  - This resolves `P3-056`; recall can only return later as a typed feature.
- Deleted missing-`FORGE.md` preflight pass-through.
  - `runPreflightValidation()` now returns a failing `FORGE_BLUEPRINT_MISSING` result when a module lacks required top-level or substep Forge instructions.
  - This resolves `P3-090`.

### STRICTIFY_TS_SLICE
- Preflight blueprint loading is now explicit and typed by result code.
  - `FORGE_BLUEPRINT_MISSING`
  - `FORGE_BLUEPRINT_READ_FAILED`
  - `FORGE_SUBSTEP_INVALID`
- Substep preflight validation now concatenates all configured substep `FORGE.md` files only after proving every configured artifact exists.
- Prompt/preflight/validation owners now run as native erasable TypeScript while their `.js` files are pure import-path facades.

### KEEP_TYPED_POLICY retained
- Missing/unreadable Forge and Buster prompt inputs still become controlled runner results instead of uncaught process crashes.
- Backend package prompt guidance remains evidence-based and appears only when `backend/package.json` exists.
- Gate-fix and review-fix prompt anti-pattern sections still preserve prior no-change attempts as retry context.
- `makePromptResult().toString()` remains a transitional prompt return-shape adapter.
- `runModulePreflight()` still accepts an omitted options object as a defensive helper shape.
- Delivery lint still passes modules without `test_config.serve.dockerfile`.
- Static-path delivery lint remains optional and avoids false failures when COPY lines are absent or unparsable.
