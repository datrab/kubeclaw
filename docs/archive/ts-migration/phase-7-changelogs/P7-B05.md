## Behavior changes

### DELETE_LEGACY
- Deleted the remaining JavaScript implementation authority for status-store, status-store lifecycle, and status-store compatibility owners.
- Deleted silent lifecycle storage fallback when neither `_runLogDir` nor `_logDir` is initialized.
  - Lifecycle event/read-model storage now throws `lifecycle storage requires initialized _runLogDir or _logDir`.
  - This resolves `P3-088` by requiring initialized run-log-dir authority for canonical lifecycle writes instead of silently deriving or skipping storage.
- Removed legacy status snapshot authority from scheduler/dependency/recovery call paths.
  - `loadStatus()` now projects from lifecycle read models.
  - Raw `status.json` reads are isolated to explicit diagnostic compatibility readers and tagged as legacy evidence.

### STRICTIFY_TS_SLICE
- `appendLifecycleEvent()` now requires `refs.primary_ref.id`.
  - This resolves `P3-086` by requiring primary lifecycle references for canonical writes.
- Malformed lifecycle storage/read/write paths now throw typed errors at the lifecycle storage boundary instead of becoming absent/empty state.
  - This resolves `P3-087` by preventing malformed canonical lifecycle signals from silently normalizing into authoritative read models.
- Gate-status compatibility projections remain diagnostic evidence only.
  - `gate-status.json` cannot grant gate completion authority, scheduler authority, or rate-limit authority.
  - Canonical gate output/completion evidence remains the authority.
- Legacy module status projection is disabled by default.
  - Migration bootstrap projection requires explicit `compatibility.legacy_module_status_bootstrap_mode: 'migration_only'` and a migration-bootstrap purpose.
  - Runtime saves and scheduler reads cannot use `status.json` as module authority.

### KEEP_TYPED_POLICY retained
- Status-store remains the public facade for existing runtime callers, but its authority comes from canonical lifecycle read models.
- Diagnostic `status.json`, `gate-status.json`, and gate-output compatibility reads remain available only as tagged operator/reporting evidence.
- Guarded status saves still reject direct lifecycle-field changes unless an explicit lifecycle mutation accompanies the save.
- The retry bridge from terminal failure/block to `READY_FOR_TESTING` remains bounded compatibility policy until retry sequencing is fully typed.
- Prompt/transcript writes remain non-authoritative observability artifacts; write/copy failures report noncritical warnings.
- Gate archive calls remain defensive no-ops when the prior source artifact is absent.
- Approval wait state sync remains a compatibility bridge over canonical wait/resume lifecycle read models.
