## Behavior changes

### DELETE_LEGACY
- Deleted the legacy Nova CLI proxy that trapped dashed legacy keys on the canonical normalized flag object.
  - `normalizeNovaCliFlags()` now returns a plain frozen camelCase flag object.
  - The canonical CLI boundary no longer carries a legacy key-trap implementation once the `.ts` owner exists.
- Deleted the temp-dir context shape fallback in the Nova CLI.
  - `main()` now always uses `ctx.setTempDir(...)`.
  - The old `ctx._tmpDir = ...` compatibility write is removed now that `PipelineContext` owns the canonical setter.

### STRICTIFY_TS_SLICE
- Strictified lifecycle owner boundaries by moving the real implementation authority into native Node erasable `.ts` owners and reducing the `.js` files to pure runtime/import-path facades only.
- Strictified verification ownership to read the canonical `.ts` implementation files for source-surface checks, while keeping runtime execution paths stable through the thin `.js` wrappers.

### KEEP_TYPED_POLICY retained
- Redis-dispatched workers still pass lifecycle health checks immediately and remain outside per-task Gateway session authority.
- Transcript fallback during Gateway `unknown`/`unreachable`/status-failure health checks remains an explicit degraded observability policy instead of hidden session authority.
- Health-check degraded/restored suppression remains intact to avoid repeat log spam while still emitting recovery evidence.
- Orchestration spawn/kill telemetry and Discord notices remain non-authoritative side effects.
- Stale tracked-session cleanup remains idempotent; missing session keys still untrack stale labels without pretending a kill succeeded.
- Unconfirmed session termination still preserves tracked evidence for later reconciliation.
- Buster capability and payload aliases remain bounded external-adapter policy at the Redis task boundary.
- Reviewer spawn defaults and reviewer lifecycle notifications remain bounded external-adapter / non-authoritative policy.
- Shutdown process reaping remains narrowly scoped to known ACP wrapper processes.
- Duplicate signal suppression, interrupted-status persistence guard, and noncritical telemetry close behavior remain intact.
- CLI env fallbacks for `CURRENT_PROJECT` / `NOVA_CHANNEL` and the `config._runtimeOverrides` bridge remain accepted external-boundary policy in this batch.

## Typed/runtime implementation notes

- The seven lifecycle/CLI owners now have canonical `.ts` implementations with explicit relative `.ts` / `.js` imports suitable for native Node type stripping.
- The retained `.js` files are now pure facades that only re-export the canonical `.ts` owners; `cli.js` also preserves direct-execution dispatch for the stable runtime path.
- These migrated lifecycle owners remain highly dynamic runtime glue. To keep Phase 7 batch momentum while preserving native `.ts` execution and passing the migration gates, the new `.ts` owners currently use `// @ts-nocheck` instead of introducing broad type-only refactors in the same batch.
