## Behavior changes

- `skills/nova/pipeline/runners/pipeline-runner.ts` is now a narrow public orchestration facade. It exports only `runPipeline`, `printStatus`, `dryRun`, and default `runPipeline`.
- Runner helper authority moved to owning modules for importers/tests:
  - lock/recovery helpers from `pipeline-runner-lock.js` / recovery owner surfaces
  - scheduling helpers from `pipeline-runner-scheduling.js`
- `skills/nova/pipeline/services/failures.ts` was deleted. Callers import leaf failure owners directly:
  - `failure-semantics.js`
  - `failures/classification.js`
  - `failures/presentation.js`
  - `failures/retry-policy.js`
- Added a contract wrapper for runtime collision checks so P6-B02 focused validation can assert packaged runtime owner/import health through the contracts suite.

## Imports, docs, and tests updated

- Runtime callers no longer depend on the broad failure barrel.
- Behavior and contract tests that need scheduler/lock/failure helpers import the owning modules directly.
- Docs now state that `services/failures.js` has no public namespace authority and that `pipeline-runner.js` is a narrow public orchestration facade.

### STRICTIFY_TS_SLICE strictified

- No P6-B02 row required additional `STRICTIFY_TS_SLICE` behavior changes beyond preserving the previously strict runtime-context failure mode.

### DELETE_LEGACY deleted

- `skills/nova/pipeline/services/failures.ts` broad public failure barrel was deleted completely.
- `pipeline-runner.js` no longer re-exports scheduling, terminal, loop, start, lock, or recovery helpers.
- `skills/nova/pipeline/core/runtime.ts` remains absent; runtime state is owned by `core/runtime.ts`, which throws when no explicit/bound/active run context exists instead of inventing a fallback identity.
- `skills/nova/pipeline/index.ts` remains narrow: config loader, shutdown hooks, status/exit constants, `runPipeline`, and default runner only.
