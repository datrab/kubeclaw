## Behavior changes

### DELETE_LEGACY
- Deleted Forge transcript-activity authority for no-work failures.
  - Forge no-change handling no longer uses transcript freshness/activity as outcome authority.
  - Failure text now requires typed completion evidence instead of transcript heuristics.
- Deleted Forge-only soft PASS on Git commit/push problems.
  - Forge-only PASS now requires durable Git persistence.
  - Commit/push failure returns an explicit terminal error instead of logging degraded and continuing PASS.
- Deleted Buster queued-suite fallback to `'none'`.
  - Buster dispatch now requires a typed nonempty `test_suites` list before queueing.
- Deleted Buster pre-test verdict-presence authority.
  - Buster terminal pre-test handling now requires explicit typed `failure_class` evidence.
  - `source`/`verdict` text alone no longer authorizes pre-test routing.

### STRICTIFY_TS_SLICE
- Strictified Buster failure-class authority.
  - `module-worker-control-results.ts` now requires explicit typed `failure_class` for non-pass module-buster outcomes.
  - Worker-control pass mapping no longer treats `poll_result.ok === true` as PASS when terminal status is `FAIL` or `BLOCKED`.
- Strictified Buster dispatch identity authority.
  - `createModuleBusterCompletionIdentity()` validates `runId`, `moduleId`, positive integer attempts, and a non-negative integer `nowMs`.
  - `deps.nowMs()` is validated before use; invalid clock evidence now throws instead of silently falling back.
- Strictified poll-failure status authority.
  - `buster-phase/poll-failure.ts` now records explicit `status_authority` evidence.
  - In-memory status is only used with degraded evidence when worker final status and poll result status are both absent.

### KEEP_TYPED_POLICY retained
- Existing module-stage defaults and dependency short-circuit behavior remain intact.
- Retry-loop continuation and retry-grace behavior remain intact.
- Validation state reset/marking behavior remains intact.
- Optional artifact refs and compatibility projections remain only at documented external boundaries.
  - Compatibility projections remain projections only; they do not authorize worker outcomes.

## Typed/runtime implementation notes

- All migrated runner/worker owner files now use native Node erasable TypeScript style only.
- Explicit relative `.ts`/`.js` imports were updated across runtime, verification, and docs surfaces.
- Node built-in imports in migrated TS islands use local `@ts-expect-error` comments where ambient Node types are not installed for the migration island.
- Lifecycle-guarded verifier fixtures were upgraded to save canonical transition objects instead of mutating guarded fields raw.
