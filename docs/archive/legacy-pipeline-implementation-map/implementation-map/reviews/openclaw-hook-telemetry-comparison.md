# OpenClaw Hook Telemetry Comparison

Source inspected: `https://github.com/comet-ml/opik-openclaw` cloned at `/tmp/opik-openclaw.o7N8im/opik-openclaw`, commit `0f62b10`.

## Finding

`opik-openclaw` is using OpenClaw's plugin hook system directly, not deriving these events from the Gateway API. Evidence:

- `src/openclaw-plugin-sdk.d.ts` declares `OpenClawPluginApi.on(event, handler)` and `onDiagnosticEvent(...)`.
- `src/service/hooks/llm.ts`, `src/service/hooks/tool.ts`, `src/service/hooks/subagent.ts`, and `src/service.ts` register handlers with `api.on("...")`.
- `README.md` says non-bundled installs need plugin hook access via `hooks.allowConversationAccess: true` because the plugin traces prompts, responses, tools, and finalization events.

At the time of this comparison, pipeline observability was mostly domain telemetry plus ACP/Gateway polling/read-models and was not wired to native OpenClaw plugin hooks. Phase 6 supersedes that state: hook-derived Redis control events are the exclusive lifecycle authority.

## Recheck notes

The complete `api.on(...)` hook set in the inspected plugin is: `llm_input`, `llm_output`, `before_tool_call`, `after_tool_call`, `subagent_spawning`, `subagent_spawned`, `subagent_delivery_target`, `subagent_ended`, `agent_end`, and `tool_result_persist`. The only non-`api.on(...)` runtime event subscription found is `onDiagnosticEvent(...)` filtered to `model.usage`.

Phase 6 follow-up implemented after this comparison:

- Control-stream Redis writes now use bounded retry/backoff before drop/dead-letter.
- The writer flushes control events before payload events to preserve lifecycle priority for events such as `openclaw.agent.ended` and `openclaw.subagent.ended`.
- Writer status now exposes per-stream queued/enqueued/written/dropped counters, retry/dead-letter counters, Redis connection state, registered hooks, and last error metadata through the plugin service `status()` method. A first-class `api.registerCli(...)` command remains optional future operator UX.
- Pipeline runtime now enables `kubeclaw-agent-observer` with `openclaw plugins enable` only for active pipeline runs and disables it in cleanup.
- Recheck against `opik-openclaw` commit `0f62b10` found one stop-drain hardening gap: Opik waits for `flushQueue` before final shutdown. `AgentObserverRedisWriter.flush()` now returns any in-flight flush promise so `stop()` waits for active Redis writes before closing the client.

Remaining non-blocking differences after the recheck:

- Opik implements `api.registerCli(... commands: ["opik"])` for `opik configure/status`; kubeclaw has service `status()` plumbing and a backlog item for `openclaw kubeclaw-agent-observer status`, but no CLI command yet.
- Opik implements `tool_result_persist` transcript mutation for media/path sanitization. Kubeclaw intentionally keeps transcript persistence mutation separate from the observer plugin; add only if runtime transcript-persistence redaction becomes an explicit requirement.
- Opik has stale trace cleanup because it owns long-lived tracing spans. Kubeclaw emits discrete lifecycle/telemetry events and does not keep span state in the plugin, so stale span cleanup is not directly applicable.
- Opik uploads media attachments to its backend. Kubeclaw currently records normalized payload evidence and relies on existing artifact/redaction paths; attachment upload is not needed unless ClawDeck wants first-class media artifact previews.

Non-telemetry OpenClaw plugin APIs that matter if we mimic this pattern:

| OpenClaw plugin API surface | Where found in `opik-openclaw` | Why it matters for kubeclaw-main |
| --- | --- | --- |

## Architectural implication

If these hooks are available in our OpenClaw runtime version, they are a better observability input than polling the Gateway for LLM/tool/agent lifecycle details. The clean architecture would be:

1. Keep Gateway wrappers for command/control operations only: spawn, stop/kill, steer/nudge, and platform health. Gateway status/liveness responses must not become lifecycle completion authority or degraded fallback observability.
2. Add a separate common OpenClaw hook adapter for observational events: LLM start/end, tool start/end, model usage, agent/subagent finalization.
3. Normalize hook events into our existing telemetry contract with new event types where needed (`agent.ended`, `agent.tool.started`, `agent.tool.finished`, optional `agent.llm.started/completed`).
4. Preserve current redaction rules at the hook boundary before any telemetry/event/artifact write.
