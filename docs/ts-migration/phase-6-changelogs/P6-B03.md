## Behavior changes

- Nova Git worktree durability is now owned by `git-worktree.ts` with erasable TypeScript annotations and explicit `.ts`/`.js` imports.
- Polling pull safety fails closed when upstream lookup cannot prove the local branch has no unpushed commits. The previous inspection-failure behavior no longer silently treated the branch as safe.
- The dormant destructive rebase recovery branch was deleted. Pull-before-push can still auto-resolve canonical runtime-state conflicts, but non-runtime conflicts abort and surface manual recovery instructions instead of resetting the worktree.
- Blueprint list/release flows now fail when the architecture branch fetch fails. They no longer continue from possibly stale `origin/<project>/architecture` cache.
- Blueprint selected-path commit idempotency remains: no selected changes returns success/no-op, and already-committed selected paths remain success.
- Blueprint rebase/push conflict recovery no longer uses pipeline-file/path heuristics. Rebase conflicts surface as failures with involved conflict paths.
- Gate/control file release/sync remains non-authoritative, but failures now return typed degraded startup evidence records instead of being only log lines.
- `preparePipeline()` collects gate/control degraded evidence into `config._startupDegradedEvidence` while preserving the non-critical startup behavior.
- Git soft-fail degraded telemetry remains caller-owned through the shared helper, now migrated to `git-soft-fail-observability.ts`.

## Ledger compliance

### KEEP_TYPED_POLICY retained

- `gitCommitAndPush()` selected no-change behavior remains intentional: no staged changes returns `{ committed: false }` instead of failure.
- Blueprint release idempotency remains intentional: an already materialized module/gate/control selection can return a success/no-change result.
- Git soft-fail commit/push policy remains intentional and caller-selected via `{ softFail: true }`; orchestration callers still emit degraded telemetry through `emitGitCommitPushSoftFailDegraded()`.
- Runtime-state-only rebase/stash conflict auto-resolution remains limited to canonical `.swarm` runtime artifacts.

### STRICTIFY_TS_SLICE strictified

- Gate/control release and sync fetch/checkout/commit failures now return typed degraded evidence (`blueprint_gate_fetch_failed`, `blueprint_gate_checkout_failed`, `blueprint_gate_commit_failed`, `blueprint_control_fetch_failed`, `blueprint_control_checkout_failed`, `blueprint_control_commit_failed`).
- `preparePipeline()` retains non-critical startup flow only by preserving that typed evidence in `config._startupDegradedEvidence`.
- Polling upstream lookup errors now fail closed with `upstream_lookup_failed` instead of silently assuming no unpushed commits.

### DELETE_LEGACY deleted

- Deleted the old `.js` owners for Git worktree, blueprint, and Git soft-fail observability after migrating their implementations to `.ts`.
- Deleted the dormant destructive reset/recovery branch from Git pull recovery.
- Deleted blueprint fetch local-cache fallback for list/release paths.
- Deleted blueprint pipeline-file-only rebase conflict auto-recovery heuristics.
