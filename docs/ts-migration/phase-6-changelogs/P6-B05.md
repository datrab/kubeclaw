## Behavior changes

### DELETE_LEGACY
- Deleted age-only stale module recovery reset authority.
  - Stale `IN_PROGRESS`/`TESTING` module states without typed active-session evidence no longer reset to retry status from timestamp age alone.
  - The recovery path now leaves status unchanged and writes durable operator evidence with `stale_module_recovery_requires_session_evidence`.
- Deleted silent scheduled-validator completion corruption fallback.
  - Unreadable scheduled-validator completion state now throws a repair-required error instead of treating the completion set as empty.
- Deleted silent unknown execution target fallback.
  - Non-string/empty execution-order entries and strings that do not resolve to a typed module, gate, or validator now fail instead of being skipped or treated as modules.

### STRICTIFY_TS_SLICE
- Strictified malformed stage refs.
  - `buildStageRefs()` rejects malformed nonempty ref specs instead of silently omitting them.
- Strictified generator config source resolution.
  - Generator input config now records a single source and rejects ambiguous project-config plus progress-config merges.
- Control file release/sync degradation remains surfaced as typed startup degraded evidence.

### KEEP_TYPED_POLICY retained
- Pipeline run lock timing, malformed-lock blocking, stale lease reclamation, and rightful-owner release checks remain intact.
- Completion idempotency remains intact for already-completed read models and already-terminal lifecycle append attempts.
- Terminal cost reporting remains best-effort noncritical observability.
- Optional artifact refs still include only materialized artifacts.

## Typed/runtime implementation notes

- All migrated owners use native Node erasable TypeScript style with explicit relative `.ts`/`.js` imports.
- Node built-in imports in migrated TS islands use local `@ts-expect-error` comments where ambient Node types are not installed.
- Pipeline runner imports and verification runtime import paths were updated to the canonical `.ts` owners.
