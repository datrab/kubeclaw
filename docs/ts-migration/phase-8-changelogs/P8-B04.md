# P8-B04 — Pipeline Runner Scheduling, Recovery, and State Machine

## Scope

- Audited the pipeline runner startup, scheduling, recovery, state-machine, dependency, and facade surfaces against the Phase 8 fallback ledger.
- Locked existing strict runner behavior with focused contract coverage for stale recovery, scheduled-validator completion state, control-file degraded startup evidence, and typed next-step planning.
- Updated migration docs for the hardened pipeline scheduling authority.

## Fallback-Ledger Decisions

- `P3-063` is resolved as `DELETE_LEGACY`: stale module status recovery no longer resets from age alone; without typed active-session evidence the status is left unchanged and durable operator evidence is emitted.
- `P3-064` is resolved as `DELETE_LEGACY`: unreadable `scheduled-validator-completions.json` state fails closed with a repair-required error instead of being treated as an empty completion set.
- `P3-065` is resolved as `STRICTIFY_TS_SLICE`: gate-file release and control-file sync remain non-authoritative startup aids, but failures are preserved as typed degraded startup evidence.
- `P3-066` is resolved as `DELETE_LEGACY`: state-machine planning requires explicit typed next-step kinds and unknown execution-order targets fail validation instead of defaulting to module work.
- Pipeline runner `.js` facades remain accepted external adapters only; behavior is owned by the paired TypeScript files and guarded by the runner facade contract.

## Changes

- Updated `tests/verification/contracts/check-pipeline-runner-slice-surface.mjs`:
  - added source/runtime guards that `planPipelineStep` rejects unknown or missing next-step kinds;
  - added a scheduler guard that unknown `execution_order` targets must resolve to typed module/gate/validator targets;
  - added a corrupt scheduled-validator completion fixture that must throw a repair-required error;
  - added stale no-session recovery guards for durable evidence and unchanged status;
  - added a startup preparation fixture proving gate/control sync failures are retained in `_startupDegradedEvidence`.
- Updated stale-recovery support behavior:
  - recovery attempts are normalized back to numeric telemetry values after canonical active-session identity supplies attempt as a string;
  - `recovery.stale_reset` and `recovery.stale_blocked` now have deterministic lifecycle idempotency keys so restart recovery can append durable lifecycle evidence.
- Updated pipeline/restart-recovery behavior fixtures to seed initialized run log paths, canonical active-session identity, and explicit lifecycle mutations.
- Updated the Phase 8 plan, authority registry, architecture map, and import/call graph to record the hardened pipeline runner policy.
