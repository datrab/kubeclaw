# P8-B06 — Review Gate Runner and Durable Publication Policy

## Scope

- Audited review gate control, fix-cycle, output parsing, runner policy, and one-cycle task execution against the Phase 8 fallback ledger.
- Hardened review lint setup, reviewer identity, review output publication, artifact fan-out observability, and canonical review output vocabulary.
- Updated migration docs, platform config, behavior fixtures, and contract checks for the hardened review gate policy.

## Fallback-Ledger Decisions

- `P3-067` is resolved as `STRICTIFY_TS_SLICE`: configured review lint is required setup evidence by default and fails the review attempt with durable `review_lint_setup_failed` evidence when generation fails. Warning-only lint is retained only when `lint_required: false` explicitly names optional lint policy.
- `P3-068` remains `KEEP_TYPED_POLICY`: review evidence fan-out artifacts are observability side effects; write/copy/archive failures do not override the review verdict, but now emit durable `review_artifact_write_failed` operator evidence.
- `P3-069` is resolved as `DELETE_LEGACY`: review output Git publication still uses the shared soft-fail Git helper, but degraded publication returns `ok:false` with `output_publication_failed` and cannot soft-pass the review result.
- Review remediation limits and timeouts are strictified into typed review config policy from the gate or `config.review_defaults`; the review path no longer falls back to global `default_max_fails` or `default_timeout_minutes`.
- Reviewer identity is strictified: remediation receives an explicit reviewer label or a normalized typed primary reviewer. Multiple reviewers without primary policy now fail setup instead of silently choosing reviewer index 0.
- Review output parsing is canonical at the typed runner boundary: `GO` and `NO-GO` are accepted; legacy `PASS`/`FAIL` aliases are not accepted inside the runner parser.

## Changes

- Updated `review-gate-runner.ts`:
  - normalizes review config into reviewers, primary reviewer policy, timeout policy, max fix-cycle policy, lint tier, and lint required/optional policy;
  - treats a single configured reviewer as named `single_configured_reviewer` policy and requires explicit primary reviewer policy when multiple reviewers exist;
  - preserves setup failure telemetry/Discord behavior while expanding setup validation to typed timeout, remediation limit, reviewer, and lint policy.
- Updated `review-gate-task.ts`:
  - uses `reviewConfig.primaryReviewer` instead of reviewer index fallback;
  - fails required lint setup with durable `review_lint_setup_failed` evidence;
  - records non-authoritative lint/prompt/transcript/archive/merged-output artifact failures as durable `review_artifact_write_failed` warnings;
  - keeps review output publication degradation as a failed review result with `output_publication_failed`.
- Updated `review-gate-fix-cycle.ts` to carry the typed primary reviewer into active-session metadata.
- Updated `config.ts` and the charted platform config to require/set `review_defaults.lint_required`.
- Updated behavior fixtures to mark test review lint as explicitly optional.
- Updated focused contracts for review primary reviewer policy, required/optional lint policy, durable review artifact observability, canonical GO/NO-GO parsing, and review publication degradation.
