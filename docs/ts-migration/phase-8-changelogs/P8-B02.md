# P8-B02 — Module Worker and Typed Worker-Control Authority

## Scope

- Tightened Nova module worker-control result construction.
- Removed Buster worker failure-class inference from reason strings, final status, camelCase compatibility fields, and legacy Redis entry fields.
- Canonicalized module worker inputs onto typed `ids`, `refs`, `worker`, and `executionContext` before Forge/Buster worker logic reads identity fields.
- Strengthened the worker-control contract check so deleted Buster failure-class behavior cannot return.

## Fallback-Ledger Decisions

- `P3-047` is resolved as `DELETE_LEGACY`.
- Buster worker failures now require explicit typed `failure_class` evidence from the worker result or the typed poll/status result.
- Reason-only, status-only, camelCase `failureClass`, and legacy Redis `_redis_entry.failure_class` shapes are rejected for Buster failure classification.
- Worker input identity fallbacks remain only as boundary normalization into typed `ids`/`refs`/`executionContext`; control-result builders no longer read legacy top-level module identity fields.

## Changes

- Updated `skills/nova/pipeline/agents/module-worker-control-results.ts`:
  - removed legacy `failureClass` and `_redis_entry.failure_class` failure-class authority;
  - removed top-level `workerInput.moduleId`, `workerInput.attempt`, and `workerInput.moduleDir` metadata authority;
  - preserved pass handling for successful Buster results without treating terminal status as failure-class evidence.
- Updated `skills/nova/pipeline/agents/module-workers.ts`:
  - added typed worker input normalization at the backend boundary;
  - removed reason/status/default Buster failure-class inference;
  - stopped passing inferred `unknown`, `blocked`, or `verdict_fail` classes to worker-control construction.
- Updated `skills/nova/pipeline/services/polling-dual.ts` so event-driven Buster completion failures emit explicit typed `failure_class` values before reaching worker-control construction.
- Updated `tests/verification/contracts/check-worker-control-result-surface.mjs` with runtime and source guards for the strict Buster failure-class boundary.
- Updated focused behavior/contract fixtures to provide canonical worker/lifecycle evidence instead of legacy reason/status-only or Redis-entry-only failure classification.
- Updated Phase 8 authority and architecture docs for the worker-control contract.
