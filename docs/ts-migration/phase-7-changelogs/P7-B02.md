## Behavior changes

### DELETE_LEGACY
- Deleted the Buster runner pre-dispatch `gate-status.json` PASS/OK compatibility read as gate-completion authority.
  - First-attempt resume now only skips on canonical `output_file` PASS.
  - Legacy `gate-status.json` can still exist as diagnostic/local evidence elsewhere, but it no longer wins pre-dispatch authority in the runner.
- Deleted Buster terminal PASS persistence to legacy gate-status/output-file artifacts.
  - PASS no longer writes synthetic `gate-status.json`.
  - PASS no longer synthesizes a missing `gate.output_file`.
  - PASS no longer attempts soft-fail Git persistence for legacy gate-status side evidence.

### STRICTIFY_TS_SLICE
- Strictified the canonical ownership boundary by moving all ten gate-support owners into native Node erasable `.ts` files and reducing the `.js` files to pure re-export facades only.
- Strictified Buster remediation request authority.
  - `buildBusterRequestFixControlResult()` now requires an explicit typed remediation policy.
  - Hidden defaults for `attempt`, `maxFixCycles`, and `rerunStageId` no longer come from missing status/config fields inside the control helper.
  - The terminal handoff now passes one canonical typed remediation policy object at emission time.
- Strictified Buster dispatch identity generation.
  - `createBusterGateCompletionIdentity()` now owns dispatch-id generation directly instead of exposing an optional timestamp fallback parameter.
- Strictified pipeline runner “started” detection toward the authoritative read model.
  - `hasModuleStarted()` now relies on canonical lifecycle fields (`started_at`, `current_phase`, `current_attempt`, history, non-pending status) and no longer treats legacy compatibility-only fields as start authority.

### KEEP_TYPED_POLICY retained
- Invalid or missing approval timeout policy still fails safe to `BLOCK`.
- Approval identity/state normalization still accepts mixed edge naming at the external boundary while preserving canonical snake_case persisted state.
- Local/Redis Buster completion compatibility parsing remains bounded external-adapter policy.
- Malformed optional Redis `verdict` JSON still does not mask a terminal FAIL result.
- Completion adapter fatal failures and timeouts still become durable operator-visible failing poll results.
- Buster failure-class inference, issue extraction, and correlation alias resolution remain external compatibility projections only; they are not promoted to new primary authority.
- Fix-cycle stale artifact cleanup remains best-effort and does not block retest after a committed fix.
- Buster prompt artifact write failures remain observability-only and non-authoritative.
- Pre-dispatch Buster config validation still fails closed through a typed `config_invalid` result instead of throwing out of the gate flow.
- Redis completion archive failure still fails closed before dispatch.
- Scoped dependency injection seams in `buster-gate-runner` and `pipeline-runner-deps` remain intentional test/harness policy.
- Bounded terminal correlation backfill in `pipeline-runner-shared` remains intentional policy without re-authorizing arbitrary nested compatibility shapes.
- Remediable Buster gate `request_fix` handoff remains the valid typed scheduler policy.

## Typed/runtime implementation notes

- The migrated gate-support owners now use explicit relative `.ts` / `.js` imports compatible with native Node type stripping.
- As in the prior Phase 7 batch, these dynamic runtime glue owners currently use `// @ts-nocheck` to preserve batch scope while still satisfying the native `.ts` runtime/import gates.
- `pipeline-runner.js` remains the public JS facade, but it now imports the canonical `.ts` support owners instead of routing through compatibility `.js` wrappers internally.
