## Behavior changes

### DELETE_LEGACY
- No P7-B04 `DELETE_LEGACY` rows were in the batch scope.

### STRICTIFY_TS_SLICE
- `telemetry-stream.ts` now requires canonical typed stream inputs at the owner boundary.
  - Stream emission is enabled only by `config.telemetry.enabled === true`.
  - `runId` must be supplied through the explicit options object.
  - The stream owner no longer falls back from `config.telemetry.stream_key`, `config._runId`, or `config.run_id`.
- `system-io-warning.ts` now passes an explicit `runId` into telemetry-stream emission rather than relying on stream-owner config aliases.

### KEEP_TYPED_POLICY retained
- Discord delivery, audit, and stat failures remain nonblocking side effects with degraded/restored evidence.
- Notification dispatch still treats missing/disabled listeners and individual listener failures as observability degradation, not pipeline authority.
- Telemetry builder helpers continue to emit nonblocking events.
- Approval timeout presentation still defaults fail-closed to `BLOCK` unless `CONTINUE` is explicit.
- Observability degraded/restored helpers still suppress repeated transitions while preserving restored signals.
- Telemetry dispatch still validates payloads, isolates sink failures, attempts disk audit append, and keeps operator alerts durable before Discord presentation.
- Telemetry sink dispatch still isolates per-sink failures and continues later sinks.
- Telemetry Redis client init/runtime/close failures remain nonblocking observability results/incidents.
- Telemetry progress defaults remain a bounded external polling adapter policy.
- Telemetry Redis shutdown remains idempotent in the stream owner.
- Truth-drift completion adjudication still refuses to invent completion drift without completion evidence.
