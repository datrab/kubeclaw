# Documentation Conventions

Document implemented behavior in the present tense. Put planned behavior in a page with a designed status.

Every published page must declare status, audience, owner, evidence, applicable version, and verification revision.

Use direct technical English. Keep descriptive sentences to 25 words or fewer. Keep procedural sentences to 20 words or fewer.

Use one action in each numbered step. State the expected result after a procedure.

Do not use vague terms such as `simply`, `obviously`, `properly`, or `easy`. Name the exact condition or action.

Use canonical project terms. Do not create aliases for contracts, lifecycle states, components, or capabilities.

Link factual claims to current source or permanent verification. Publication changes local evidence into release-pinned source links.

Keep migration history in internal changelogs and implementation records. Do not put migration history in operator instructions.

Automation applies an ASD-STE100-inspired check. Technical review remains necessary because automation cannot certify the complete ASD-STE100 specification.
