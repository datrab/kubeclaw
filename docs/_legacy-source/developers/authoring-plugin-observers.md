# Authoring Plugin Observers

Declare subscriptions, ordering, failure policy, capabilities, configuration
schema, and checkpoint schema in `plugin.json`. Observer code receives one
immutable `ObserverDelivery` and a revocable, registration-scoped context.

Observer handlers must:

- project events deterministically;
- use only declared capabilities;
- use stable event or delivery identity for externally visible resources;
- redact confidential values before persistence;
- tolerate duplicate delivery;
- return no scheduler result and attempt no lifecycle mutation.

Do not include delivery-attempt numbers or timestamps generated by the
observer in an idempotent sink payload. Those values change across retries and
would conflict with the stable capability idempotency key. Attempt diagnostics
belong in core's delivery journal.

Use `best_effort` for presentation or optional telemetry. Use `required` only
for an operator-designated audit/compliance sink whose failure must fail the
host operation.

Every observer package needs TypeScript or native-language tests for:

- each subscribed event projection;
- duplicate and out-of-order input;
- redaction and size bounds;
- capability denial;
- timeout, cancellation, sink failure, and plugin crash;
- retry, checkpoint, restart, and deterministic redelivery;
- replacement and removal;
- required failure behavior, when applicable.
