# API object updates

A changed manifest is an input to an update operation. It is not the complete object that Kubernetes will validate. The client can combine that input with a stored object and earlier configuration. The API server then applies defaults, admission and update validation. Read the field's receiver contract after selecting the operation below.

A **field manager** is the identity recorded with a managed set of fields. A **last-applied configuration** is the manifest stored in an annotation by client-side apply. These are different state. Neither permits a change that fails parent validation, an immutable-field check, access control or admission policy.

This page describes source behavior. No API request, rollout, hook, eviction, cache event or volume publication was executed for this explanation. The source dependencies are Kubernetes `66452049f3d692768c39c797b21b793dce80314e` (v1.35.0), Argo CD `e258ee23c3e52266d407572f4bcdfe7d9ed36cb5`, its kubectl v0.36.1 dependency `01cb18cdbab1c5d4fd4dd0fc7005789d35989d22` and apimachinery v0.36.1 dependency `7af103a2a439106791220493349f8d13bc0a1efd`. Argo embeds `gitops-engine` in the same Argo source tree. Its client dependency differs from the API-server authority; do not substitute one revision for the other. The platform operator owns actual client, server and policy selection.

<a id="client-side-apply"></a>
## Client-side apply

Client-side apply first reads the live object. If it is absent, the client records the apply annotation, removes null-valued map entries and creates the object. Fresh typed decoding/defaulting follows at the API server. A null manifest leaf at this create step therefore cannot be treated as a retained typed scalar null case. A present list element or its parent can still fail decoding or validation. [v1.35 create route](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/kubectl/pkg/cmd/apply/apply.go#L672-L703), [Argo's v0.36.1 client create route](https://github.com/kubernetes/kubectl/blob/01cb18cdbab1c5d4fd4dd0fc7005789d35989d22/pkg/cmd/apply/apply.go#L672-L703).

For an existing Deployment, the client obtains the old manifest from the last-applied annotation. It builds a strategic merge patch from three objects: that old manifest, the new manifest and the current live object. It combines changes from current to desired with deletions from old to desired. A field removed from the old manifest can therefore be deleted; outside a selected `retainKeys` directive, a field absent from both old and new manifests is not deleted merely because it exists in live state. Malformed stored annotation data or missing list merge keys can stop patch construction. A missing annotation is warned about; it does not turn the operation into server-side apply. [v1.35 patch selection](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/kubectl/pkg/cmd/apply/patcher.go#L117-L206), [three-way construction](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L2127-L2152), [Argo client patch selection](https://github.com/kubernetes/kubectl/blob/01cb18cdbab1c5d4fd4dd0fc7005789d35989d22/pkg/cmd/apply/patcher.go#L118-L193), [Argo client's three-way construction](https://github.com/kubernetes/apimachinery/blob/7af103a2a439106791220493349f8d13bc0a1efd/pkg/util/strategicpatch/patch.go#L2123-L2147).

Deployment `spec.strategy` uses `retainKeys`. When the generated patch includes a `$retainKeys` list, applying it removes live strategy keys outside that list. For example, changing the desired strategy to `type: Recreate` can remove live `rollingUpdate` settings even if the old applied manifest never contained those settings. The directive must include every nonnull key supplied in that patch; an invalid directive fails. Inspect the selected client and resulting patch before relying on omission to preserve a live strategy member. [Strategy patch declaration](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/api/apps/v1/types.go#L394-L397), [retained-key construction](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L224-L232), [directive validation and removal](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L1070-L1099).

An explicit null in the resulting strategic patch removes that map member. A nonnull object patch merges its children. An empty object consequently does not clear every existing child. Lists with a strategic merge key combine matching items and preserve unrelated items unless a deletion or replacement directive applies. Lists without strategic merge instead replace as a complete list; for those lists, `[]` clears the list. Changing a merge-key value selects another item identity; it is not a rename of the existing item. The field reference exposes each list's actual strategic merge key beside its schema. [Strategic null and nested dispatch](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L1360-L1435), [merge versus replacement list handling](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L1475-L1490).

Client-side apply defaults `overwrite` to true. It can overwrite a different live value; it does not run the server-side apply ownership-conflict check. With overwrite false, a conflicting change against the old manifest causes patch construction to fail. API conflicts trigger bounded re-read and patch reconstruction. Client force deletion is a separate option: after a conflict or invalid update, it can delete and recreate the object. Those force flags are absent from the selected deployment-script apply calls. If force recreation is explicitly enabled elsewhere, restoration of the old object after create failure is only an attempt and can itself fail. The original object UID and its workload lifecycle are not restored by creating a new object. [Default overwrite](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/kubectl/pkg/cmd/apply/apply.go#L177-L192), [construction conflicts](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/strategicpatch/patch.go#L2161-L2178), [retry and conditional recreation](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/kubectl/pkg/cmd/apply/patcher.go#L358-L412).

<a id="argo-operation-selection"></a>
## Argo operation selection

Argo passes Application options into the sync engine. Resource annotations and operation settings then affect the selected request. Replacement takes precedence over apply: for a live Deployment it uses replace, and for an absent Deployment it uses create. Force on the replacement route selects delete/recreate. These are whole-object operations; omitted fields do not have three-way apply preservation. For ordinary apply, Argo sets overwrite true. When it selects server-side apply, it sets `ForceConflicts` true independently of its client force-deletion setting. A live Deployment with another manager can therefore lose that manager's conflicting ownership under the selected Argo SSA route. Do not interpret `Force=false` as SSA conflict protection. [Controller option binding](https://github.com/argoproj/argo-cd/blob/e258ee23c3e52266d407572f4bcdfe7d9ed36cb5/controller/sync.go#L319-L331), [replace/apply choice](https://github.com/argoproj/argo-cd/blob/e258ee23c3e52266d407572f4bcdfe7d9ed36cb5/gitops-engine/pkg/sync/sync_context.go#L1400-L1442), [Argo apply options](https://github.com/argoproj/argo-cd/blob/e258ee23c3e52266d407572f4bcdfe7d9ed36cb5/gitops-engine/pkg/utils/kube/resource_ops.go#L432-L469), [kubectl replace versus force](https://github.com/kubernetes/kubectl/blob/01cb18cdbab1c5d4fd4dd0fc7005789d35989d22/pkg/cmd/replace/replace.go#L253-L311), [force deletion and absence wait](https://github.com/kubernetes/kubectl/blob/01cb18cdbab1c5d4fd4dd0fc7005789d35989d22/pkg/cmd/replace/replace.go#L315-L371).

Argo disables SSA during its client dry run and when the target resource has the disable-SSA annotation. Otherwise Application SSA or the target SSA annotation selects it. Selected client-side ownership migration runs before the final request, can modify managed fields and can fail synchronization before that request. Even a selected replacement passes through this earlier migration condition when SSA is also selected. The operator must inspect both desired and live annotations, manager state and migration result. A diff result or dry run does not prove the operation that the real synchronization will send. [SSA predicate](https://github.com/argoproj/argo-cd/blob/e258ee23c3e52266d407572f4bcdfe7d9ed36cb5/gitops-engine/pkg/sync/sync_context.go#L1281-L1296), [migration before operation](https://github.com/argoproj/argo-cd/blob/e258ee23c3e52266d407572f4bcdfe7d9ed36cb5/gitops-engine/pkg/sync/sync_context.go#L1400-L1418).

<a id="server-side-apply"></a>
## Server-side apply

SSA sends an unstructured apply object with a manager and a force-conflicts choice. The API server converts the stored and submitted objects using the API schema and calculates managed field sets before defaulting the merged result. It rejects a submitted managedFields member and duplicate submitted list identities. A field omitted by this manager can be removed only when this manager previously applied it and no other applier retains ownership. A field never owned by this manager is not removed by that omission. A changed field that intersects another manager's fields produces a conflict without force; force transfers conflicting field ownership. An equal value can be co-owned. Parent atomic boundaries and list identity decide the size of that ownership set. [Apply request and force](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apiserver/pkg/endpoints/handlers/patch.go#L499-L540), [typed conversion and later defaults](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/util/managedfields/internal/structuredmerge.go#L121-L181), [conflicts and ownership transfer](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/merge/update.go#L131-L147), [manager omission and pruning](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/merge/update.go#L209-L279).

The field reference preserves `x-kubernetes-list-type`, map atomicity and SSA list map keys. For example, container ports have strategic merge identity `containerPort`, but SSA identity includes both `containerPort` and `protocol`. A TCP-to-UDP change can consequently act on a different SSA item while the strategic route matches the same numeric port. An atomic list such as arguments is managed as a whole; a keyed list such as containers gives each name its own member identity. Atomic selector objects make their children share the atomic ownership boundary. Do not apply a scalar ownership rule to a child inside one of these atomic parents. [Container fields and port identities](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/api/core/v1/types.go#L2920-L2953), [container keyed membership](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/api/core/v1/types.go#L4127-L4135), [atomic label selector](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/staging/src/k8s.io/apimachinery/pkg/apis/meta/v1/types.go#L1268-L1281).

The structured validator accepts null scalar, map and list values. Scalar and atomic map/list merge keeps a present submitted null as that leaf value; later conversion/defaulting and validation determine its typed result. A null item inside a keyed associative list instead fails before merge. Granular maps and associative lists merge their members: a submitted null or empty collection is not a blanket removal of live members. SSA first merges, then removes previously owned members that this manager omitted and that no other manager retains. Null and an empty map also contribute their parent path to the submitted field set; ownership can consequently differ from an absent parent. This explains why a typed omission case cannot predict an SSA clear. [Null scalar validation](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/typed/validate.go#L88-L116), [null collections and rejected keyed null items](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/typed/helpers.go#L161-L206), [submitted leaf precedence](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/typed/merge.go#L57-L68), [list/map merge boundary](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/typed/merge.go#L340-L426), [null/empty map field membership](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/vendor/sigs.k8s.io/structured-merge-diff/v6/typed/tofieldset.go#L151-L179).

<a id="parent-validation-and-recovery"></a>
## Parent validation and recovery

Every selected operation must produce a whole Deployment that passes its selected API route. A changed selector is rejected on normal update, even with force-conflicts. A template must match that selector, use restartPolicy Always and contain valid containers; a retained nonempty ephemeralContainers list is forbidden. Changing only replicas follows scaling; changing the template can create a new ReplicaSet and new Pods. It does not change those fields in existing Pods. Normal Deployment update preserves stored status; a `/status` request selects separate validation, including nondecreasing collisionCount. [Deployment update strategy](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/registry/apps/deployment/strategy.go#L109-L135), [selector immutability](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/apis/apps/validation/validation.go#L709-L713), [template validation](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/apis/apps/validation/validation.go#L833-L855), [ephemeral prohibition](https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/apis/core/validation/validation.go#L7075-L7078).

The platform/workload operator must retain the desired manifest, the selected options, the live object, the stored apply annotation or managed fields, and the actual request/error. If construction, ownership or admission fails, stop before treating the field as effective. Correct the exact input or agreed ownership boundary, read current state again and inspect the subsequent admitted object. After an uncertain response, establish whether the request took effect before repeating a force or replacement action. API success is only the next boundary: verify the selected controller, new Pod, scheduler, volume, identity or application observation separately. No procedure on this page claims those observations were executed.
