## Purpose

Use this catalogue to identify the authority system that interprets a capability name.
Nova grants and Buster runtime capabilities are separate allowlists.
A shared name does not transfer a Nova grant into Buster or a Buster route into Nova.

## Choose the Owning Authority

Start with the component that rejected the operation, not with a matching capability string. These namespaces do not form one permission list.

| Namespace | What the declaration means | Enforcement and reader route | No automatic translation |
| --- | --- | --- | --- |
| Nova plugin registration | `requiredCapabilities` requests authority; `providesCapabilities` offers an implementation. | The platform grant resolver selects providers and grants constraints; invocation checks the stage lease. Use the Nova tables and platform policy below. | Neither declaration grants permission by itself. A Buster test-provider declaration uses its own runtime namespace. |
| Buster test-provider runtime | A provider requests named runtime operations. | Buster resolves the provider and checks its configured runtime routes; use the Buster table below. | A Nova grant does not install a Buster route or bypass Buster admission. |
| Worker profile and attempt | Profile `capabilities` bounds the attempt; `grantedCapabilities` must be a subset. `resourceCapabilities` describes measurement semantics, not permission. | [Worker profiles, engines, and roles](worker-profiles-and-roles.md) explains profile digests, host admission, budgets, and measured results. | A matching `artifacts.read` or `network.http` string is not a Nova lease or a Kubernetes permission. A profile declaration is not a measured observation. |
| Kubernetes RBAC | Roles bind API verbs, resource types, and scopes to a Kubernetes subject such as a ServiceAccount. | [Security and trust](../understand/security-and-trust.md) separates API authority, workload identity, network access, and plugin leases. | Neither a Nova grant nor a worker capability grants Kubernetes API access. RBAC does not authorize an unrelated application HTTP operation. |
| Codex plugin interface | The Ops plugin advertises `Read` in `interface.capabilities`. | [Codex integration](../understand/codex-integration.md) follows the separate MCP connection, bearer check, API token, and RBAC boundaries. | `Read` is interface metadata, not a Nova grant, a Buster route, or an enforcement guarantee. The optional Ops Pod can separately grant namespace-scoped pod exec. |

For a denied Nova call, check the requesting registration, selected provider, grant constraints, and concrete lease operation/resource. For a Buster denial, check the provider request and runtime route separately.
For worker admission, compare the advertised profile digest, attempted capability subset, and host resource policy. For a Kubernetes denial, inspect the actual caller ServiceAccount and bound API verb/resource/namespace; do not broaden a plugin grant to fix RBAC.
For a Codex/MCP failure, distinguish connection authentication from Kubernetes authorization. Stop before changing policy when the rejecting boundary or caller is unknown. Do not grant across namespaces by name matching or assume that an unchanged retry will change authorization.

## Platform Grants Are Not Swarm Roles

The chart ships a compact `swarm.config.json` with `profile: "standard"` and empty `overrides`.
Its current standard-profile expander does not produce `roles`, `grants`, or `providers` fields.
Adding any of those fields through compact overrides is rejected as an unsupported effective config path; it does not grant Nova authority.

> [Compact chart configuration](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/charts/kubeclaw/files/config/swarm.config.json); [standard profile and override validation](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/tests/verification/e2e/support/platform-config.ts); [expanded standard profile](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/tests/verification/e2e/support/config-profiles/standard.json).

Nova instead loads a separate `pipeline-platform.v2` configuration.
`providers` maps each capability name to a provider registration identity; `grants` maps a requesting registration identity to capability-specific constraint objects.
These keys identify registrations, not operator roles. A provider selection alone does not grant a consumer permission.
For an enabled registration, a requested capability without configured constraints fails with `REGISTRY_CAPABILITY_DENIED`.
A configured grant for an unrequested capability or a disabled registration fails with `REGISTRY_CAPABILITY_UNREQUESTED`.
Resource scopes use the constraint lists in the vocabulary above; invocation authorization additionally checks the concrete operation and resource.

> [Platform schema](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/skills/common/plugin-runtime/foundation/config/platform.schema.json); [platform loader](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/skills/common/plugin-runtime/foundation/config/platform.ts); [grant and provider resolution](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/skills/common/plugin-runtime/foundation/registry/capabilities.ts); [resource authorization](https://github.com/datrab/kubeclaw/blob/7994a51e16bc752357c3a801190b12b7d6a191a4/skills/nova/core/execution/authorization.ts).

Stop if a procedure asks you to authorize a Nova plugin by adding a role or grant to compact swarm overrides.
Use the separately validated Nova platform policy and the plugin registration requirements instead. Do not infer a role-to-grant translation or an effective deployment policy from the chart defaults.

## Names Used By Both Systems

Some names occur in both tables because both systems describe the same external action.
Each system still performs its own admission check and uses its own request contract.
Configure and verify both boundaries when Nova submits work that Buster later executes.
