# 05 Acceptance Suite Plan

## Target Shape

Build a strict acceptance suite that runs real producers and consumers with injectable runtime adapters, and keep static tests only as secondary drift guards. The acceptance suite should fail whenever an emitter and consumer disagree on schema, identity, artifact authority, state location, or degraded runtime behavior.

## Migration Order

1. Freeze current suite with this catalogue; do not delete tests yet.
2. Add acceptance harness utilities: temp repo, temp swarm_dir, real Redis container or required external Redis, gateway/session fake, deterministic clock, and artifact inspectors.
3. Port the known regressions first: task identity, suite timeout, capabilities, output_file, completion/ack, stale evidence, manual fallback.
4. Reclassify rewritten tests from REWRITE/AMBIGUOUS to KEEP/CONTRACTED only when they prove emitter-consumer behavior.
5. Demote static contract scripts to drift guards after corresponding acceptance tests exist.
6. Make release gate run: unit helpers, acceptance suite, live Redis smoke, runtime startup smoke, final gate hardening, deploy smoke where available.

## Release Gate Definition

A release cannot pass unless all pipeline-critical acceptance tests pass, every degraded/manual fallback maps to explicit terminal state, and no AMBIGUOUS or BROKEN behavior remains in the behavior catalogue.
