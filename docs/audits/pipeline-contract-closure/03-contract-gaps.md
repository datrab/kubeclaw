## Known Regressions Coverage Map

- Missing `timeout_seconds`: now covered across Nova producer, Redis envelope, and Buster validator by `check-nova-buster-task-envelope-acceptance.mjs`; live Redis/processTask lifecycle remains G1.
- Missing `completion_stream`: now rejected by `validateBusterTaskPayload` and covered by `check-nova-buster-task-envelope-acceptance.mjs`; `ensureTaskTerminalBeforeAck` now dead-letters missing `completion_stream` before ACK instead of returning clean `no_completion_stream`.
- Missing `commit_hash`: now covered by the same cross-boundary acceptance test.
- Missing `session.runtime` and `session.agentId`: now covered for produced Buster task payloads; still needs session launch acceptance for both ACP and subagent.
- Suite timeout/config: all-suite missing/invalid timeout and unknown-suite rejection is now CONTRACTED; add valid minimal-config execution fixtures where safe.
- Missing/denied capabilities: Buster suite denied-capability matrix now emits explicit critical ERROR verdicts and durable operator alerts; unavailable Redis/gateway/deploy adapters remain follow-up.
- Missing output artifact: Buster `output_file` authority acceptance now proves missing/stale output becomes terminal FAIL; needs terminal session acceptance through agent/session runners.
- Identity mismatch: output_file, completion, latest pointer, plugin artifact, diagnostic fallback, active session, and gate evidence checks now exist; live Redis duplicate/conflict surfaces remain environment expansion.
- Missing Redis completion: completion-before-ack and completion selection proof now exist; add live Redis no-completion timeout and terminal decision proof.
- Stale lock/session/artifact: restart recovery authority now rejects file-only/stale active-session authority, artifact authority rejects stale non-authoritative evidence, and lifecycle replay overrides stale projections; add replacement-session race fixture.
- Terminal agent error without valid output: must be accepted only as failure/block.
- Path-only Discord notification: now rejected for critical/actionable notification-hook presentations and WARN/ERROR/CRITICAL telemetry sink presentations by `check-notification-operator-identity-acceptance.mjs`; existing valid notification-hook WARN/CRITICAL status presentations remain accepted.
- Manual fallback treated as clean success: first generic degraded-evidence terminal guard is now CONTRACTED; remaining fallback sources need matrix coverage.
