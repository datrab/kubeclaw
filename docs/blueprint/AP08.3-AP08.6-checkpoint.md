## Result

These four parts replace a high-level extension summary with four task guides. The
guides explain the current implementation in direct technical English. They define
KubeClaw terms before they use those terms for detailed behavior. Each important
choice includes its practical reason, cost, failure consequence, and supported
alternative. The guides use narrow links to production code at the assessment
revision. They do not copy production code into manually maintained examples.

AP08.3 explains the five pipeline registration contracts. It follows the data,
authority, lifecycle, compatibility, and failure path for stages, observers,
capability adapters, test providers, and report adapters. A comparison table makes
the ownership differences explicit. The page also identifies shortcuts that the
runtime does not support.

AP08.4 uses Blueprint Sync and the state-store adapter as concrete effectful
examples. It explains effect identity, business idempotency, capability order,
receipts, uncertain outcomes, retry, resume, cancellation, cleanup, and the state
store limit. The guide does not imply that a journal can undo an external mutation.

AP08.5 follows a Buster declaration through suite resolution, provider execution,
evidence collection, and report normalization. It distinguishes the 17 test
providers, two fixture providers, one report adapter, and 12 suite templates. It
also explains ports, retry ownership, cancellation, cleanup, and evidence limits.

AP08.6 explains Nova's 21 stages and six adapters. Nova owns no observer package at
this revision, so the guide uses the shared observer contract and Nova's delivery
runtime instead of inventing a Nova-owned example. The page also explains the lint
stage, lint adapter, policy versions, rule changes, role selection, and bundle
inspection.

## Local Platform Limits

The host has BusyBox `flock`. The persistent runtime calls GNU
`flock --timeout`. Persistent effect, state, observer recovery, adapter cleanup, and
Buster attempt-store checks therefore stop at lock acquisition. This result is a
host-tool incompatibility. It is not a pass and it is not evidence of a plugin
failure.

The host also has no `cc` executable. The plugin sandbox build exits before it can
create the sandbox launcher. The Buster report-runtime test then reports
`REPORT_ADAPTER_SANDBOX_NOT_BUILT`, and the runtime bundle builder stops at the same
build prerequisite. The package-local JUnit adapter test does not need that launcher
and passed.

The capability-security check still contains a fixed expectation of 24 capability
identifiers while the current runtime exposes 28. This pre-existing test drift does
not change the source-backed contract descriptions. AP08 does not change product
security code to make a documentation check green.

The Nova lint type-evidence exercise and all eight remediation tests passed. Its
live-function test reached `FileEffectJournal` and then stopped on the same BusyBox
`flock` incompatibility. AP08 therefore records the rule and process-control checks
as passed, but it does not report the complete package command as passed.

## Detailed Quality Recheck

The second full reading used the requested quality criteria instead of relying on
the initial structural checks. It found one factual defect: the effect guide said
that Blueprint Sync declared four capabilities. Its manifest declares five because
approval and lineage processing can use `artifacts.read`. The guide now names all
five and links the complete manifest.

The recheck also found that the Buster and Nova pages explained several authoring
decisions only through surrounding text. They now state the problem, selected
boundary, benefit, cost, rejected alternative, and reconsideration condition.

The guides now include complete implementation sequences for these tasks:

- selecting and implementing one of the five pipeline contracts;
- building and testing an effectful stage;
- changing a suite safely;
- building a Buster provider and adding it to the Buster role;
- building and bounding a report adapter;
- building a Nova stage or capability adapter;
- building and packaging a shared Nova observer;
- changing lint policy, a policy pack, or lint engine code.

Each sequence points to a maintained implementation, manifest, test, role, or
runtime path. The pages contain command blocks, but no copied production-code block.
The automated check now enforces these sections and the no-copy rule.

## Completion Decision

AP08.3 through AP08.6 are complete for their documentation scope. The maintained
checks prove page structure, code links, current contract counts, suite counts,
role composition, the JUnit adapter, and the effect behavior that does not need a

This decision does not claim that the unavailable persistent or sandbox-dependent
checks passed. It also does not claim live deployment, a complete package catalogue,
or an end-to-end `.swarm/pipeline.json` run. The guides place each local limit next
to its verification command. AP08.10 still requires an independent reader exercise
without chat history. AP08.7 is next.
