Choose the authority before freeing space

A store holds data for a named consumer. Authority is the retained data needed to decide or recover an operation. A projection is a derived view. A cache is an optimization only where its owner establishes rebuildability. A file called temporary, spool or cache can still contain irreplaceable output or unresolved ownership; its name is not deletion permission.

  1. Identify the configured root, actual deployment/mount and writer/reader.
  2. Select the complete consistency group, not one convenient journal or database.
  3. Distinguish capacity, retention, expiry, compaction and domain-authorized retirement.
  4. Before backup, restore or cleanup, follow the existing owner's procedure and writer fence. Stop if original identity, quiescence or the recovery path is unknown.

A consistency group is the data that must represent one compatible point. Quiescence means the owning work has stopped, not only that a timeout expired. Use Recovery for the canonical state/owner selector and Define a Backup Set for credentials, independent destination, schedule, retention, loss/time targets and restore proof. This reference explains boundaries; it does not introduce a competing backup workflow or claim that the procedures have run.

Distinguish retirement from arbitrary cleanup

The Foundation's explicit durable-record retirement API rechecks the exact selected v2 records, owner and payload digest under the real store writer fence, and calls the domain authorizer there. It retains tombstones and a retirement receipt to preserve replay identity and requires positive byte saving. A tombstone retains identity/history without the original payload. This is not evidence of a connected age scheduler, applicability to every state/wait/telemetry owner, or deletion of every referenced blob.

Buster compaction has a different contract: completed job with result, no cleanup errors or incomplete attempts, bounded readable evidence, verified retained source and positive net metadata savings. It retains a compacted header/receipt. Its terminal-workspace helper deletes only reproducible input copies—repository.tar.gz, workspace/repository, and workspace/test-provider-snapshots—after the terminal caller owns quiescence. Workspace, scratch, evidence, artifacts, observability, job records and logs are explicitly not generic disposable input copies. An invalid/replaced parent or uncertain orphan owner is a stop, not permission for recursive cleanup.

Backup groups and original-reader proof

Use the existing Backup Set, Prism Backup Group, Pipeline State Recovery and Verification procedures. Required credentials, clients/versions, independent destination, capacity/time bounds and writer fences belong to those procedures. Do not substitute another parser, client, server or source identity to obtain a successful-looking restore.

A database migration also changes state. Prism's runner sorts selected SQL filenames, locks the migration transaction and applies unapplied names. The ledger records names, not a checksum comparison of previously applied SQL. A changed SQL file under an already recorded name is therefore not proved rejected by that ledger. Retain the exact migration/application versions and use the original consumer's supported direction; do not invent rollback.

Audit and inspection are not universally write-free

Audit adds no new lifecycle/audit entry, but its actual FileJournal construction prepares the parent, opens/creates a stable append-lock and uses /usr/bin/flock. Loading a nonempty journal without a final line feed (LF) truncates to its last LF, possibly zero bytes, and synchronizes before parsing committed chain/hash records. Empty/LF-terminated bytes do not need tail repair; lock metadata effects remain. Invalid committed data can still fail.

Missing events.jsonl fails before construction (AUDIT_JOURNAL_MISSING); missing run selection fails afterward (AUDIT_RUN_MISSING). Even a failed lookup can already have changed bytes. Before audit or retry preserve the first diagnostic, partial output and original evidence. Do not assume interruption left bytes unchanged. Where original bytes must be retained, use only a correctly bound inactive copy of the run root, not the sole retained original; audit can modify that copy too. Preserve run/head binding and do not merge outputs from different runs or journal heads.

Follow the canonical Pipeline State Recovery order: stopped owners, verified raw run/adapter copies, strict copied-journal inspection, then the original supported audit/recovery route only when its prerequisites pass. Do not use audit to make a corrupt copied journal pass. No read-only/no-record bypass flag, pure-parser substitute or general repair guarantee is asserted. Other durable-store readiness/reads can acquire locks; qualify the actual call path instead of labelling every read write-free.

Respond to loss or pressure without destroying evidence

  • Full store: preserve the first admission error, configured quota dimension, actual owner/root and retained liability. Do not delete another store or raise a host bound without its authority. Use explicit retirement only where the domain proves records no longer needed and its supported API authorizes it.
  • Missing blob/result: retain metadata, reference digest, original request and source bytes if available. Repair through the owning idempotent write or supported backup route; do not invent content or a terminal receipt.
  • Expired lease or unknown native owner: stop new conflicting work until host identity, quiescence and accepted effects are reconciled. Time expiry alone is not deletion permission.
  • Corrupt journal or partial restore: retain raw bytes and diagnostic; keep writers fenced. Restore the complete group only through its supported procedure, not a silent tail edit or single-file replacement.
  • Lost cache/projection: use the owner's established rebuild/replay path only from retained authority. Where no path or source remains, report the gap rather than claiming recovery or re-executing a business action.

Expected recovery proof includes original application readers, accepted identities/permissions, referenced artifacts/effects, cleanup and measured loss/time separately from targets. LiteLLM isolated operator restore, application verification and cutover are not supplied by the current native backup/test alone. Prism's independent failure-domain recovery is also not proved by its same-server SQL smoke test.

Coverage and maintenance limits

The named roots and selected deployment routes above are finite. All SQL tables/migrations, host/OpenClaw/Codex/operations state, cluster/Secrets/SPIRE, every PVC/cache/mirror, external receiver and conditional retention owner are not globally inventoried here. Absence from this page is not proof that data is disposable or a conditional supported route is irrelevant.
