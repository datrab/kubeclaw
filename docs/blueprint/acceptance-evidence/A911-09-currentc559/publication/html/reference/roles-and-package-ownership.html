Inspect bundle selection without starting a runtime

Run these steps at the repository root on a development machine with Node.js 24. They need read access to checked-in manifests. They do not need cluster access, credentials, installed plugin activation, or a bundle output directory. See developer setup for the supported development environment.

  1. Check node --version. Stop if this is not the selected Node.js 24 development environment.
  2. Print the authoritative role selections:
node --input-type=module <<'NODE'
import fs from 'node:fs';
for (const role of ['nova', 'buster', 'prism']) {
  const file = `packaging/runtime/roles/${role}.json`;
  const manifest = JSON.parse(fs.readFileSync(file, 'utf8'));
  console.log(JSON.stringify({
    role: manifest.role, entrypoint: manifest.entrypoint,
    packages: manifest.packages, plugins: manifest.plugins,
    extensions: manifest.extensions,
    externalCapabilities: manifest.externalCapabilities,
  }, null, 2));
}
NODE
  1. Check declared selection and dependency closure:
node scripts/check-runtime-role-manifests.mjs

Prism: exported engine is not the native host

The Prism facade exports its engine, worker binding, and domain. An embedding caller constructs PrismEngine with a DesignProvider. The worker binding accepts only contract kubeclaw.prism-design-engine@1, supported operations generate, render, evaluate, ingest, and publish, and the installed request schema ID and digest. It validates the request and result around the supplied engine call. Schema rejection is not authorization to retry with another contract. Prism runtime exports. Prism engine caller/provider boundary. Prism worker operation binding.

The native per-attempt host is a different consumer. It constructs PrismEngine(new DeterministicDesignProvider()); it does not read a role field to select an external design provider. It reads a bounded worker envelope from stdin, validates it, runs WorkerAttemptExecutor, and emits its provisional result. Closing stdout does not make this result final. The supervisor first drains the owned process tree, then checks the provisional result against the accepted attempt. It applies the final observed resource use and host timestamps; a host fault or expired claim can turn a reported completion into an error. It calculates a new result digest and receipt identity and checks the final attempt binding. The journal then stores the canonical result bytes before delivery. This makes the final record distinct from the child's earlier stdout; it does not prove that external cleanup succeeded. process-tree drain and final observation. result finalization and identity. journal result-byte boundary. finalize and persist before returning. native host engine and envelope.

Worker listener, supervisor, and child have different inputs

The Prism listener selects either SPIFFE peer identity, as defined above, or HMAC (hash-based message authentication code). HMAC uses a shared secret to check a code calculated from the request's timestamp, nonce, and body digest. A nonce is a per-request value whose reuse the nonce store rejects; this path needs the database as well as the secret. It is not the Buster bearer-token comparison and does not select a design provider. Prism HMAC calculation. Prism time, signature and nonce checks. listener authentication selection.
