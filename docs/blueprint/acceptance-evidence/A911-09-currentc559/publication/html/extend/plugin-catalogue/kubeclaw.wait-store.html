Purpose

Create and read durable wait records through signal.wait.

When To Use It

Use it when Core needs storage for a wait owned by a pipeline attempt.

When Not To Use It

Do not use it to authorize a signal or decide that a waiting stage can continue.

Most Important Limit

The adapter stores waits. Core validates signals and owns wait resolution and continuation.

Failure Behavior

Create checks typed wait fields and expiry; read retrieves a stored wait. Reusing a key with different wait content fails with WAIT_IDEMPOTENCY_CONFLICT. Signal authorization and continuation remain Core responsibilities.

Registry validation checks declared paths, schemas, and capability names. Activation or the Buster loader checks executable exports; discovery does not import package code. The surface runtime rejects a missing grant or resolved-plan binding before unauthorized work. The selected runtime owns failure recording and lifecycle state. Package code does not gain lifecycle authority. Adapter startup cleanup can remain pending when shutdown ignores its abort signal; follow the startup stop rules.
