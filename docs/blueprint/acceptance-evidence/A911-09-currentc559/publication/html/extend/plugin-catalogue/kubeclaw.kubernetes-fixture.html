Purpose

Prepare and clean a Kubernetes fixture for Buster tests.

When To Use It

When Not To Use It

Do not use it for permanent application deployment.

Failure Behavior

Preparation returns deployment evidence and, when requested, credential provenance. With delete retention, cleanup calls release and requires a successful response. With retain retention, provider cleanup does not request release; lease expiry and controller retention policy still bound the lifetime. Provider-level tests do not prove deletion in a real cluster. Use Prepare and release a Kubernetes fixture for the supported Buster entry point, required authorities, expected outputs, retention and failure recovery.

Registry validation checks declared paths, schemas, and capability names. Activation or the Buster loader checks executable exports; discovery does not import package code. The surface runtime rejects a missing grant or resolved-plan binding before unauthorized work. The selected runtime owns failure recording and lifecycle state. Package code does not gain lifecycle authority. Adapter startup cleanup can remain pending when shutdown ignores its abort signal; follow the startup stop rules.
