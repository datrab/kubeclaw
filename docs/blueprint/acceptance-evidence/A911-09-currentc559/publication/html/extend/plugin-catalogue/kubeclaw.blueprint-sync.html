Purpose

Synchronize blueprint content into the implementation workspace.

When To Use It

Use it when an approved blueprint must become a bounded repository change.

When Not To Use It

Do not use it to approve unreviewed architecture or arbitrary files.

Approval checks depend on supplied ancestor evidence. Source-less execution is supported and does not prove approval; the graph must require the intended approval step.

Failure Behavior

The stage synchronizes control paths, commits the workspace change, appends state, and stores an artifact. Supplied approval evidence must match the source paths and revision.

Registry validation checks declared paths, schemas, and capability names. Activation or the Buster loader checks executable exports; discovery does not import package code. The surface runtime rejects a missing grant or resolved-plan binding before unauthorized work. The selected runtime owns failure recording and lifecycle state. Package code does not gain lifecycle authority. Adapter startup cleanup can remain pending when shutdown ignores its abort signal; follow the startup stop rules.
