Start with the changed behavior

A nested configuration field changes its default. Updating a table is not enough: the consumer may apply a different default, an operator may need a restart, and an old example may now request the wrong behavior. This workflow connects the source change to its explanation, generated facts, failure path, and reader task. Use it for a new surface, a changed meaning, and a removal. A documentation agent uses the same steps and stop conditions as a human maintainer.

Use the Developer handbook for component-specific owners and checks. Use documentation governance for canonical homes and source authority. This page joins those rules into one change procedure; it does not replace the component's technical guide.

Prepare a bounded change

  1. Start from a checkout whose revision and existing changes you can identify. Record the changed source paths, selected tools, dependency state, and intended outputs. Preserve unrelated work. Use the handbook's checkout and component preparation before running tools.
  2. Name the reader's question and the behavior owner. Distinguish product source, a supported dependency configuration, a generated fact, and explanatory prose. A schema declaration alone does not prove a consumer inserts its default.
  3. Open the page map. Locate the source dependency or parent component and its owner, page, and declared checks. Read the actual generator's boundary and the actual consumer. If no mapping exists, assign an owner and canonical page before calling the change covered.
  4. Identify permissions and effects before execution. Node.js 24 and locked root dependencies are common prerequisites, not the whole toolchain. Follow the selected-route tools for any Helm, Go, Kubernetes, native, or other requirement. A source or local check is not a live deployment result. Missing prerequisites stop that route; do not switch to a partial parser or omit a source to obtain a green result.

Keep a small change record: source boundary, parser/selector, owner, canonical page, generator or manual explanation, check, reader task, and exclusions. This record is a work aid. Registering it does not prove discovery complete. The generated page map lists metadata dependencies and check names, but does not itself inventory every public surface, run a reader task, or choose every test.

Discover the whole affected family

Search the source boundary before selecting a convenient example. Include conditional and disabled supported branches, shared helpers, generated names, and callers that change defaults or authority. Read the actual extractor's roots, exclusions, and supported syntax. An unsupported source form is a blocker for that extractor, not proof that the surface does not exist.

Link applicable upstream definitions while explaining the choice KubeClaw makes.

Choose one fact authority and its explanation

Put a mechanical fact in its source and let its owning generator derive it. Write the reason, operational consequence, compatibility, and safe recovery in the authored page. Do not manually maintain a second list of generated fields.

Preserve the immutable baseline; do not recapture it to conceal a new or moved file. The generic tree tooling and publication selector must agree. Non-Markdown reader assets need their separate allowance.

Prove the changed meaning, not a fixed count

Choose the smallest complete checks for the affected source and consumer. For a nested default change, verify the actual absent-input result, an explicit accepted value, an invalid value, and any conditional branch that changes the default or authority. For a removed error identity, verify its absence from current output, the retained dynamic family, and the changed safe-action text. Do not mutate production source as an experiment while another task uses it.

Use isolated fixtures for addition, semantic change, and removal in each affected reference family. First demonstrate a healthy baseline. Introduce one mutation, require the intended drift failure and named affected page, restore the fixture, and require recovery. A generic parser crash or unrelated stale file is not the intended rejection. New-source and passive-neighbor cases distinguish discovery from a hard-coded expected count. Preserve current bytes and the fixture diff. The existing configuration mutation suite creates a temporary tree, copies inputs, and starts generator/publisher child processes; it also queries Git. It is not a no-write check. Inspect its current scope and dependencies before selecting it, and do not apply its results to untested error/event/store families.

Validate examples against their actual contract, not merely JSON syntax. Record the schema/version, consumer, setup, expected output, failure/cleanup, and any external effects. Execute only in the documented isolated or authorized environment. The publication checker has selected plugin and resume-signal schema examples; that does not validate every operator or infrastructure command. A compiled example is not evidence of activation, recovery, or a live service.

Ask independent readers to use the page without chat history or undocumented maintainer hints. Give a concrete Find, Understand, and Act task chosen before they read it. For the default example: find the field, explain which consumer wins, identify restart/new-run impact, choose the valid override and safe rejection response. Retain missing steps as defects. Independently check source accuracy and language/navigation quality; the author cannot supply all of those independent observations by rereading the same draft.

Rename, retire, and recover

Before removing a page or source identity, account for every still-valid claim, consumer, generated row, example, incoming link, owner, and historical route. Move required information into its canonical successor and verify parity before deleting the old authority. Use the route registry and governance for a genuine public rename, not for a fabricated former URL. Preserve fragment targets or explicitly migrate them. The registry's structural validation does not prove server or static redirects; test real old/new requests and anchors in the selected renderer. The repository's transition tooling has its own manifests, source snapshots, child checks and effects. Read that contract before a destructive transition; an unrelated prose change does not require or permit a retirement run.
