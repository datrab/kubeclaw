Choose the smallest owner

Use this router before changing an internal component. First ask whether an existing extension contract can contain the behavior. If it can, use that extension's guide instead of changing the platform. A package's presence does not grant permission to activate it or establish a ready native host. Start with the request-to-result path and role and package boundaries.

A contract is a versioned boundary between a caller and its receiver. An invariant is a rule that must survive every supported action. A reducer computes the next state from the current state and a result. Replay reconstructs state from retained records. A receipt records an external operation's outcome; an HTTP response alone is not necessarily that receipt. Idempotency keeps one logical request from causing duplicate work. Fencing rejects work when the current owner cannot prove authority. A digest identifies bytes or one declared encoding, not permission or health.

Prepare and finish one bounded change

  1. Follow Prepare a clean checkout. Select the actual full source commit for your change. Use its lockfile and selected tools; do not substitute a global compiler or a live run directory. The handbook's historical example commit is not a universal current baseline.
  2. Name the caller, receiver, data/authority handoff and invariant. Record which old inputs, active runs or stored records must still work. Choose one route below.
  3. Trace changed configuration through validation, defaults, effective caller, capture time and receiver. Use configuration change impact and precedence. A values edit does not move stored data; a restart does not grant capabilities.
  4. Change the owning source, not a generated copy. Add positive and denied-neighbor cases for the changed rule, plus interruption/replay/compatibility cases when state or effects cross the boundary. Select the smallest complete chain from the component route and command tables, not an arbitrary single green test.
  5. Update the canonical explanation, affected operator task and recorded source dependency. Use documentation maintenance for its tools, generation ownership and drift checks. Keep original failures, partial outputs and uncertain cleanup distinct from a later success.
  6. Before activation or rollout, require the actual caller/host/operator procedure and observation. A local check, generated document or compilation is not that result. For removal, first account for active users, retained versions and data; remove registration/grants/providers only through their owners' supported path.

Use Linux, Node.js 24, npm with the committed root lockfile, and the installed root compiler selected by that lockfile. Journal fixtures need genuine GNU util-linux /usr/bin/flock, a qualified local filesystem with complete append writes and synchronization, and isolated durable fixture roots. C fixtures need the C11 compiler cc. Native, Go, Helm and browser chains have additional prerequisites below. Do not run them against a deployed run or data root. The cited setup procedure includes dependency acquisition, not an offline check.

Nova and lifecycle

Nova Core is a library with a command-line interface (CLI), not an independent daemon. The selected CLI or project facade loads platform configuration and a pipeline/project, discovers the permitted packages and executes the resulting graph. The project compiler owns graph construction; scheduling owns when an eligible stage runs. Do not change one to conceal an invalid input to the other.

For a graph or invocation change, identify the actual caller variant, original platform file, run identity, package snapshot, graph digest and recorded profile. Current snapshot readers distinguish run versions v1–v4 and graph versions v2/v3; that finite support is not permission to reinterpret an unknown version. Retained recovery compares the original graph; incompatible changed input belongs to a new run, not a relabeled recovery. Platform paths resolve from the canonical configuration file's directory, not an assumed shell working directory.

Follow Change Nova lifecycle, scheduling or run authority. Select lifecycle contract checks and lifecycle/replay fixtures; add SDK/package ownership checks when schemas, packages or public contracts also change. Update Nova Core's explanation and the affected run/recovery task. On graph or snapshot mismatch stop with the original retained inputs and error; do not regenerate the old identity, delete the snapshot or start a replacement run as recovery.

Lifecycle decisions and waits

The live flow is stage result → reducer → budgeted decision → durable records and next action. applyStageResult accepts results only from running. It requires a reason for non-passed outcomes and consumes an attempt after validation. Configured technical retries have their own accounting; remediation has another budget. A new reason is not interchangeable with a new outcome or scheduling action. Completed-attempt replay calls the same reducer and repair decision; changing only live state breaks that agreement.

decisionWait binds an orchestrator wait to run, stage and attempt. Its authorized issuer and signal type are part of the continuation boundary; the orchestrator wait shown here has expiresAt: null. That does not remove validation from other wait kinds or permit a stale/foreign signal. Preserve wait identity and the original approved payload across interruption. Test allowed transitions, denied neighbor states, exhausted budgets and live/replayed equality. Include the process-death fixture, which writes a journal and kills a real Node child. See the lifecycle route and original-state recovery.

Effects and unknown outcomes

The effect coordinator checks the original idempotency request and existing receipt, acquires the resource lock, then rechecks identity under that lock. A terminal receipt returns the existing outcome without another invocation. The durable requested/accepted state separates first invocation from recovery. An accepted request without a terminal receipt uses the adapter's receipt method. If it is absent or returns no receipt, recovery stops; it does not grant a fresh effect or a new idempotency key. Generic invoke/shutdown adapters need not implement this recovery route.

Keep effect encoding/version, attempt/resource identity, lock renewal, current fence and durable result together. A renewal/release failure can leave additional failure evidence; do not hide it with a retry. Cover interruption before/after acceptance and receipt, lost response, conflicting identity, corruption and failed renewal/release. The external-effect fixture starts the real CLI and a local service, writes durable temporary state and can kill the child; it is not an inert assertion-only test. See the handbook's effect change route.

Before audit or recovery, follow Pipeline state recovery: establish the writer fence and preserve the original related stores. FileJournal construction can create a lock and truncate a nonempty incomplete tail through its last newline, possibly to zero, then synchronize it before parsing. A projected audit adds no canonical event, but is not a guarantee of unchanged storage. Preserve the first diagnostic and original bytes before an authorized inspection; never remove a live lock inode or manufacture a no-record substitute.

Worker and native host boundaries

The caller's versioned attempt/profile contract enters Worker Core. The native supervisor owns the process lifetime, sealed control channel, output spool and resource reservations. The host operator owns the root-managed launcher, policy, Linux control groups (cgroups), runtime identity and aggregate capacity. A cgroup is a kernel resource-control boundary, not a JavaScript memory limit. The pool binds the real filesystem/device/inode; a copied pathname or policy file is not proof of the original host boundary.

Follow Change Worker Core or native execution. Keep protocol/version, host/boot identity, supervisor lifetime lock, cancellation, spool sealing and recovery consistent. The spool owns bounded private output files and synchronizes accepted bytes; channel framing alone does not define durable acknowledgement. Tests must account for every owned process before cleanup or renewed admission. Preserve unresolved ownership and unfinished cleanup; do not declare ready because contract fixtures pass.

Start with Worker contract and attempt-executor checks. Select the native chain only with the genuine host, C compiler, prepared cgroups, root-owned policy, Helm/native inputs and selected Go prerequisites. The Node Resource Interface (NRI) connects the runtime to the native pool. Its builder separately checks the selected Go version and modules, requires an absent output, then writes a binary. Neither building it nor passing a render proves a supported running host.

This registry is not an Open Container Initiative (OCI) image storage server. Use Change registry, storage or package discovery. SDK and public contracts

The software development kit (SDK) exposes shared contracts to actual producers and consumers. Start with the canonical schema and encoding meaning, then the source generator, generated types/exports and every supported caller. A TypeScript optional field is not compatibility proof for a closed JSON schema. Package version, wire version, source digest and portable JSON encoding are different identities; choose the transition for the intended identity change explicitly.

Integrations and receiving services

Choose the actual package guide and the smallest complete check chain. Trace caller → admitted target → host/model/service → bounded request → persisted result and downstream consumer. Forge, Echo and service/API integrations do not share an invented start command or one generic receipt implementation. An application programming interface (API) defines the receiving operation; endpoint reachability alone does not authorize it.

For runtime dispatch, verify the selected endpoint, authentication, resource identity and limits at their real loader and receiver. HTTP means Hypertext Transfer Protocol. HMAC is a keyed message authentication code; the shown adapter signs the idempotency key and exact JSON body with a confidentially obtained secret. SPIFFE (Secure Production Identity Framework for Everyone) workload identity is a different selected trust path; do not substitute an HMAC secret. The adapter rejects oversized requests, invalid target or cancellation; a safe bounded no-follow retained-result read is not proof of successful remote work.

createDispatchAdapter exposes ready/invoke/shutdown here, not receipt. If a response is lost, preserve the request identity and receiving-service outcome; stop while it is unknown. Do not claim durable-effect recovery can reconcile an adapter that lacks its required receipt method. Run selected package and original receiving-host fixtures; use verify:prism:native-dispatch when that Control boundary changes. Complete Forge/Echo host/model/policy/version and lost-response procedures still need their own supported component path.

Studio and Archviewer

Prism Studio is a typed document editor. Archviewer is a separate static reader; neither may take over the source component's write/approval authority. Use Change UI behavior, Prism ownership and Archviewer. User interface (UI) changes must preserve domain operations, revision conflicts, preview isolation, authentication, keyboard access and responsive behavior. Preserve user intent on a stale-revision conflict rather than overwriting it.

The Studio build empties skills/prism/dist-studio; npm's prebuild:studio also generates contract validators before Vite runs. The development server binds loopback 127.0.0.1:4190. Playwright can start or reuse a server there; identify its owner/bytes before trusting a result from an already occupied port. Its declared projects cover desktop, phone and tablet sizes, not every browser. Build/test output is not publication or a deployed browser observation. For Archviewer, native nginx/OpenSSL prerequisites and the actual input document and publisher must be established separately.
