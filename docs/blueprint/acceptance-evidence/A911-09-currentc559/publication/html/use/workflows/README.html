Use these guides to bind a pipeline task to its inputs, durable state, result authority, and cleanup. A wait is a persisted request for a later decision. A resume signal supplies that decision to the same run. Resuming creates a new stage attempt; it does not change the result of the earlier attempt.

Wait, Approval, and Resume

Start with the complete approval input set. It uses the installed human-approval stage, durable wait store, and operator notification adapter. Follow the guide through the first wait, wrong wait and wrong issuer, one valid decision, exact replay, audit comparison, and cleanup. Retain the original request, notification receipt, signal bytes, and attempt counts. A notification receipt proves delivery; the signal and journal prove the later Core transition.

Configure and Operate owns run control, signal authority, interruption, and the cancellation boundary. The workflow guide supplies concrete inputs and observations for that procedure. Nova Core explains the mechanism. Workflow Reference describes the input contracts.

Select the Execution Scope

Local schema and plugin tests check their stated contracts. A supported-host rehearsal checks a disposable local run with a loopback notification receiver. A deployment run additionally needs a registered runtime, operator access, durable storage, package identities, receiver, and secret authority. Record each scope separately. Neither a unit test nor a loopback run proves deployment behavior.

The full deployment wait/resume run is mandatory and remains unexecuted. Use the deployment registration and stop conditions to identify the missing inputs. Do not infer completion from an example file, a successful notification, or a source link.
