Objective

Prepare one KubeClaw environment without hiding a missing platform dependency. Finish with ready workloads, smoke results, and an independent recovery route.

This procedure does not install a host, K3s, a storage driver, or a CNI (Container Networking Interface) implementation. CNI defines how the container runtime calls network plugins to connect containers. It starts with an existing Kubernetes cluster.

Supported Topology and Limits

The repository deploys one application namespace plus separate identity namespaces. It can also deploy a separate Ops Pod namespace.

The default application namespace is kubeclaw. SPIRE uses spire-server and spire-system. The default Ops Pod namespace is kubeclaw-ops.

The deployment path can install these components:

  • SPIRE and its CSI (Container Storage Interface) driver. CSI defines how Kubernetes uses external volume drivers; SPIRE uses its driver to deliver the workload-identity socket to Pods.
  • Redis, PostgreSQL, and LiteLLM.
  • Nova and Buster role deployments.
  • Prism and its PostgreSQL, Control, Studio, Worker, and agent workloads.
  • The Tailscale operator for the complete showcase baseline.

The deployment path does not establish these platform services:

  • Host operating system and K3s installation.
  • CNI installation or a CNI migration.
  • StorageClass creation and external backup storage.
  • An OCI (Open Container Initiative) registry or BuildKit client configuration for production use. OCI defines container image and distribution formats; the registry stores and serves those images.
  • Argo CD ownership transfer for existing Helm resources.
  • Independent host, KVM, or SSH administration.

Stop if the environment depends on an item in the second list and no operator owns it.

assert_cluster_binding() {
  test "$(kubectl config current-context)" = "$EXPECTED_CONTEXT" &&
  test "$(kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}')" = "$EXPECTED_CLUSTER_SERVER" &&
  test "$(kubectl get namespace kube-system -o jsonpath='{.metadata.uid}')" = "$EXPECTED_KUBE_SYSTEM_UID"
}
bound_kubectl() {
  assert_cluster_binding || { printf '%s\n' 'CLUSTER_BINDING_MISMATCH' >&2; return 1; }
  env KUBECONFIG="$KUBECONFIG" kubectl "$@"
}
bound_helm() {
  assert_cluster_binding || { printf '%s\n' 'CLUSTER_BINDING_MISMATCH' >&2; return 1; }
  env KUBECONFIG="$KUBECONFIG" helm "$@"
}

Check authority for the selected scope

Authorization means that the API permits this identity to perform a verb on a resource in a scope. A namespaced grant applies to one namespace; a cluster-scoped grant applies to resources such as namespaces or PVs. A PV (PersistentVolume) represents the storage backing a PVC (PersistentVolumeClaim, which requests that storage). Permission in the application namespace does not establish permission in the probe, Prism, SPIRE or Tailscale namespaces. auth can-i checks the particular verb, resource and scope. It does not prove admission, quota, node capacity or provider permission.

# Publish a writable latest copy without changing the sealed source receipt.
probe_working_copy() {
  local source="$1" destination="$2" staging
  [[ -f $source && ! -L $source ]] || return 1
  [[ ! -L $destination && ( ! -e $destination || -f $destination ) ]] || return 1
  staging="$(mktemp "$PREFLIGHT_EVIDENCE_DIR/.working.XXXXXX")" || return 1
  cp -T -- "$source" "$staging" || return 1
  chmod 0600 -- "$staging" || return 1
  [[ ! -L $destination && ( ! -e $destination || -f $destination ) ]] || return 1
  mv -f -T -- "$staging" "$destination" || return 1
}
# Each read owns new output, stderr and exit files before the working copy changes.
probe_observe() {
  local file="$1" status observation output_fd stderr_fd
  PROBE_RETENTION_STATUS=failed
  PROBE_COMMAND_STATUS=not-run
  shift
  observation="$(mktemp -d "$PREFLIGHT_EVIDENCE_DIR/observations/read.XXXXXX")" || return 1
  date -u +%Y-%m-%dT%H:%M:%SZ > "$observation/time.txt" || return 1
  printf '%s\n' "${PROBE_CAPTURE_REASON:-initial preparation}" > "$observation/reason.txt" || return 1
  printf '%q ' "$@" > "$observation/command.txt" || return 1
  printf '\n' >> "$observation/command.txt" || return 1
  exec {output_fd}> "$observation/output" || return 1
  if exec {stderr_fd}> "$observation/stderr"; then :; else
    exec {output_fd}>&- || return 1
    return 1
  fi
  if "$@" >&"$output_fd" 2>&"$stderr_fd"; then status=0; else status=$?; fi
  PROBE_COMMAND_STATUS="$status"
  exec {output_fd}>&- || return 1
  exec {stderr_fd}>&- || return 1
  printf '%s\n' "$status" > "$observation/exit" || return 1
  chmod -R a-w -- "$observation" || return 1
  probe_working_copy "$observation/output" "$PREFLIGHT_EVIDENCE_DIR/$file" || return 1
  probe_working_copy "$observation/stderr" "$PREFLIGHT_EVIDENCE_DIR/$file.stderr" || return 1
  probe_working_copy "$observation/exit" "$PREFLIGHT_EVIDENCE_DIR/$file.exit" || return 1
  printf '%s\t%s\t%s\n' "$observation" "$file" "$status" >> "$PREFLIGHT_EVIDENCE_DIR/observation-index.tsv" || return 1
  PROBE_RETENTION_STATUS=complete
  return "$status"
}

Pod Pending, Failed, image pull or mount failure Read captured Pod status and events. Capture logs only when the probe container has actually started. No started container is recorded as NOT_AVAILABLE, not as a successful DNS/storage result. Resolve the named scheduler, registry, mount or DNS owner; do not substitute a different image or class merely to pass.
Capture denied, API failure, changed namespace/Pod/PVC/PV identity The corresponding .exit/.stderr files identify the failed observation. Keep the namespace, claim and any volume. Restore the bound read authority through the platform owner, then repeat probe_capture "read authority repaired; owner permits observation" in the guarded form. Keep all previous observation and capture directories. Never interpret a denied read as absence or run deletion from stale snapshots.
PV visible but provider ID, reclaim policy or provider lookup is unknown Retain all objects. Storage owner supplies the provisioner-specific asset identity and cleanup/disposition procedure. A missing CSI handle is not evidence of an empty volume.

Recovery never proceeds to installation on a failed probe. Repeating the probe requires a corrected owned prerequisite, complete cleanup/disposition of the previous run, a new namespace name and a new evidence directory. Keep the old failure record.

Clean only the owned probe namespace

Before deletion, the cluster and storage owners must reconcile the current captured state and approve cleanup of this exact disposable namespace. The storage owner supplies a private <probe-cleanup-clearance-json> outside Git, with these fields: namespaceUID, pvcUID (the original creating UIDs), pvUID (the first observed bound PV UID, or empty for an unbound claim), providerAssetId (the known asset, or empty only after an owned provider reconciliation proves no allocated asset), safeToDeleteNamespace: true, approvedBy, and reconciliationReceipt. The receipt identifies the provider lookup, any in-progress allocation and its cancellation/quiescence result, and the asset's current disposition. Verify the owner's approval through the independent planning-record authority; checking JSON shape is not authentication of that approval. This applies to a Pending PVC too. Without that reconciliation, keep the namespace and escalate using the exact claim UID; there is no universal provider cleanup command.

Cleanup requires independently authenticated creating provenance for every created namespace, Pod and PVC, and the still-enforced lifetime exclusion. Unknown creating identities, including a present object after a failed CREATE response, forbid this default cleanup. The storage owner must authenticate the first observed PV UID, original PVC binding and provider asset against its provisioning record before approving them; a GET alone is not PV provenance. Keep these identities and the approved binding immutable. A new binding, replacement PV or different provider asset requires a new owner reconciliation, not a changed baseline or automatic approval.

Use the same bound shell. Capture again before matching the approval, because a Pending claim can bind while the owners investigate. If identities changed or a previously unbound claim acquired a PV, obtain a new clearance. For a non-CSI PV, the approved providerAssetId supplies the external identity; for a CSI PV it must agree with the observed handle.

The raw DELETE sends a UID precondition to the API, so a different namespace with the same name must not be deleted. That precondition does not freeze namespace membership, PVC binding or provider operations. The complete owned exclusion window remains required through the final independent Kubernetes and provider disposition checks. kubectl accepts a single local request-body file for raw DELETE. The local raw-request interface was checked with kubectl v1.34.11 against an isolated HTTP fixture; this is not a supported-cluster-version or live delete result. The platform owner must confirm that the selected client supports these exact flags before the probe. There is no PV deletion command in this block. A namespace deletion failure or timeout is not permission to force deletion or strip finalizers. Preserve the exact exit and snapshots; let the named cluster/storage owner reconcile finalizers and provider operations before another write. The deletion body is created once; on a failed/uncertain delete, retain it and its receipt rather than rerunning this block as a fresh deletion attempt.

Each nonempty post-delete PV observation must retain the original recorded UID. A replacement UID stops this block at its first observation, even if that replacement later disappears. Keep the original approval and all replacement stdout, stderr and exits. The cluster and storage owners must reconcile the identity violation and restore the exclusion before further action. Never change the recorded UID or treat later absence as reconciliation. A malformed or denied read, a present/replaced namespace, or exhausted original-PV polling also stops without a successful Kubernetes disposition record.

The disposition file states only the recorded API observations. No recorded PV binding does not exclude an intermediate unseen binding or provider allocation. It cannot prove continuous absence or backing-asset deletion.

After Kubernetes observations, the storage owner must run the approved exact provider lookup for PREFLIGHT_PROVIDER_ASSET_ID, or the recorded claim-based reconciliation when no asset ever existed. Save the sanitized command, time, exit status and result as provider-disposition.txt in the evidence directory. Only that owner can prove provider absence and that provisioning will not later create an orphan. Unknown provider disposition leaves the probe incomplete. Retain the image digest, class/request, approval, all creating and observed UIDs, API snapshots, events, logs or explicit no-log state, commands/exits and both Kubernetes and provider disposition records. Do not remove the evidence directory. A failed probe remains failed after cleanup; correct its cause and rerun with new identities before installing workloads.

Do not run teardown-all to repair a failed first install. It destroys the namespace and its retained state.

Use a Helm rollback only when the previous release matches current data formats. Do not roll back a database after an incompatible migration.

For a platform access failure, leave the cluster-dependent Ops Pod path. Use the previously recorded host or control-plane route.

If the cluster itself is absent, stop here. The repository has no complete host bootstrap procedure.

Cleanup

Remove only temporary DNS, storage, or access probes through the platform procedure that created them, and verify their exact names are absent. Keep failed workload resources until their events, logs, Helm state, PVC ownership, and recovery decision are retained. Do not use teardown, teardown-all, or a broad namespace deletion as first-install cleanup. After a successful install, remove restricted temporary files and credentials from the administration machine while retaining non-secret hashes and command output.
