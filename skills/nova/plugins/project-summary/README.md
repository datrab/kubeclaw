# Project delivery manifest

The summary stage produces `delivery-manifest.v2` by default from immutable artifacts supplied by the core. Set `deliveryManifestEncoding` to `delivery-manifest.utf16-v1` to select `delivery-manifest.v3`; downstream consumers must support that version. The stored artifact then uses the separate `kubeclaw-json.utf16.v1` encoding marker. Input declares module implementation/test stage identities and the final implementation/lint/test identities and optional enabled-review identity, with independently expected module and cumulative coverage policies. Run identity comes from the invocation lease.

Every selected artifact must belong to this run and the latest producer attempt. Reads verify digest and byte count within an aggregate 8 MiB bound. Module quality decisions and final lint/quality and any enabled review evidence must pass and refer to the corresponding implementation commit. The manifest records source revisions and evidence references and has its own canonical digest. Missing, conflicting, corrupt or stale evidence blocks publication.

Caller-owned status, test counts, delivery percentages and agent-invocation counts were removed: they were not execution evidence. This contract requires version-pinned draining of old graphs. The artifact-contract tests exercise actual durable storage and negative cases; they do not establish provider or agent execution. Deployment acceptance remains a separate check.

The final policy must be cumulative and contain exactly every declared module's requirements and owned paths, plus explicitly declared integration requirements. Native `test-gate-decision.v2` binds required-node outcomes to the exact resolved plan and existing signed Git source snapshot. A last-module decision cannot substitute for this policy. The manifest exposes decision/result digests and coverage bindings; it does not assert readiness, credential delivery, a retained exposure lease, or operator acceptance.

Echo defaults off in project compilation. If a final review is enabled, summary reads its actual persisted review bundle, checks report.bundleDigest, full requirement/prefix coverage and baseline-to-candidate range. A narrow or missing review cannot be accepted by copying a passing report at the same revision. Disabled Buster test-agent dispatch is explicitly recorded as disabled; the deterministic native decision remains mandatory and no agent verdict is fabricated.
