# Runtime binary security rebuilds

The Nova image uses six source-built binaries; Buster consumes the same locked
kubectl and Trivy builds. Their upstream release binaries still contain vulnerable
compiler runtimes or modules. Terraform and Hadolint remain checksum-verified
upstream artifacts.

Each directory contains a normal Go module/checksum lock. Go's checksum database
authenticates downloaded modules; the build refuses lock mutation, validates the
selected upstream module version, and compiles with the centrally pinned Go
toolchain. `versions.env` is generated by `scripts/versions.mjs`. No module version
is resolved during compilation, and no advisory is excluded from scanning.

The kubectl entrypoint is the existing Apache-licensed upstream entrypoint used
by the Ops build, linked against the selected Kubernetes client module release.
Helm marks the rebuilt tree as dirty rather than claiming an unmodified upstream
release binary.

After changing a tool version or transitive security pin, regenerate its Go locks
with the selected Go compiler, execute the real binary, and scan the resulting
binary with `trivy rootfs`. Native `build.sh` checks can set the absolute
`RUNTIME_BINARY_OUTPUT_DIR` instead of Docker's `/out`.

Buster also rebuilds BuildKit, runc and RootlessKit from their locked upstream
modules with patched archive/network dependencies. runc retains the upstream
seccomp and AppArmor build tags and static linking; its libseccomp library
comes from the same dated Debian snapshot as the worker. The npm CLI is copied
to its canonical module path, rather than replacing a lower-layer directory
with a symlink that can leave stale package inventory in image scanners.
